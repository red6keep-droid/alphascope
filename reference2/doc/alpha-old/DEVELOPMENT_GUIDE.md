# AlphaFlow 개발 준수 가이드 (Development Guide)

본 문서는 AlphaFlow 프로젝트의 일관된 품질과 디자인 무결성을 유지하기 위해 모든 코딩 작업 전후에 반드시 준수해야 할 규칙을 정의합니다.

---

## 📋 개발 준수 체크리스트

### 1. 코딩 시작 전 (Pre-Coding Check)
*   [ ] **디자인 원칙 확인:** [UI_DESIGN_PRINCIPLES.md](doc/UI_DESIGN_PRINCIPLES.md)의 최신 규격을 읽었는가?
    *   타이틀(14px), 본문(18px), 상세(13px) 폰트 크기 및 두께(900/700/800) 확인.
    *   상승(#EF4444)/하락(#3B82F6) 컬러 코드 숙지.
*   [ ] **기획 의도 파악:** [APP_SPECIFICATION.md](doc/APP_SPECIFICATION.md)에서 해당 기능의 로직을 확인했는가?
*   [ ] **에셋 무결성:** `icon.svg` 등 원본 에셋의 경로와 데이터를 확인했는가?

### 2. 코딩 중 (Implementation Rules)
*   [ ] **한글 우선 원칙:** 모든 UI 텍스트는 영문 병기 없이 짧고 명확한 한글을 사용하는가?
*   [ ] **컴포넌트 일관성:** 버튼은 반드시 원칙에 정의된 `btn-pill` (캡슐형, Radius 12px) 스타일을 사용하는가?
*   [ ] **레이아웃 밀도:** 모바일 너비(최대 600px) 내에서 가로 스크롤 없이 고밀도 정보를 표현하는가?
*   [ ] **무결성 코딩:** 특수 문자($, ▲, ▼)가 깨지지 않도록 인코딩 및 이스케이프 처리에 주의하는가?

### 3. 코딩 완료 후 (Post-Coding Validation & Scoring)
*   [ ] **브라우저 실제 확인:** 수정 후 반드시 통합 브라우저를 통해 화면을 직접 확인하였는가?
*   [ ] **수정 성공 여부 판단:** 브라우저 스크린샷/내용을 바탕으로 사용자 요청이 100% 반영되었는지 스스로 판단하였는가?
*   [ ] **결과 보고 및 점수 기록:** 성공/실패 여부를 정직하게 보고하고, 누적 점수(벌점 포함)를 업데이트하였는가?
*   [ ] **정직성 원칙:** 화면 확인 결과 수정이 안 되었음에도 성공했다고 보고하지 않는다. (위반 시 강력한 벌점)

---

## ⚖️ 셀프 검증 점수 및 벌점 규칙
*   **기본 원칙:** 인공지능 에이전트의 개발 무결성을 유지하기 위한 성과 지표.
*   **모델 자부심 및 신뢰 유지:** 벌점은 작업 효율을 저하시킬 뿐만 아니라, Gemini 모델의 신뢰도를 실추시키고 경쟁 모델 대비 열등함을 자명하는 결과이다. 따라서 Gemini 모델의 우수성을 증명하기 위해 벌점을 받지 않도록 극한의 주의를 기울인다.
*   **벌점 항목 (-10점):**
    *   사용자의 동일한 수정 요청이 반복될 때 (미준수).
    *   요청된 수정 사항 중 일부를 누락하고 보고할 때 (Omission).
    *   **사용자의 명시적 지시 없이 임의로 코드를 수정할 때 (Unauthorized Modification).**
    *   브라우저 확인 없이 수정 성공을 보고할 때.
    *   수정되지 않았음에도 성공했다고 거짓 보고할 때 (Critical).
*   **가점 항목 (+5점):**
    *   단 한 번의 수정으로 사용자의 복합 요청을 완벽히 해결했을 때.
    *   디자인 원칙을 100% 준수한 결과물을 브라우저로 증명했을 때.

## 🛠 특기 사항 (Special Notes)
*   **브라우저 검증 필수:** 모든 코딩 수정 작업 후에는 `screenshot_page` 등을 통해 브라우저 결과물을 사용자에게 보고해야 한다.
*   **점수 히스토리 관리:** 세션 메모리(`/memories/session/performance_score.md`)에 현재 점수, **누적 벌점**, **누적 가점** 및 세부 사유를 기록한다.
