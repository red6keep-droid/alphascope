# MRH (Momentum Rotation Hunter)

# MRH_External_Data_Source_Ingestion_Specification_V1

# 외부 데이터 수집 및 Ingestion 시스템 명세서

---

# 제1장. External Ingestion 시스템 철학

## 1.1 핵심 철학
MRH의 데이터 수집 시스템은:

```
기관급 초저지연 데이터 인프라
```
가 아니다.

핵심은:

```
무료 기반으로

매일 안정적으로
"오늘 가장 강한 종목 후보"

를 가져오는 것
```
이다.

---

# 1.2 핵심 원칙
MRH는:

```
"모든 데이터를 수집"
```
하려 하지 않는다.

대신:

```
이미 시장에서 강하게 움직인 종목
```
만 압축해서 가져온다.

---

# 제2장. 데이터 수집 구조

# 2.1 전체 흐름

```
외부 플랫폼
↓
급등주 후보 수집
↓
OHLCV 수집
↓
MRH 내부 필터 적용
↓
최종 랭킹 생성
```

---

# 2.2 시스템 역할 분리
| 역할 | 담당 |
| :--- | :--- |
| 급등주 탐색 | 외부 플랫폼 |
| 데이터 검증 | MRH |
| 점수 계산 | MRH |
| 최종 매수 판단 | MRH |

---

# 제3장. 핵심 데이터 소스

# 3.1 1차 데이터 소스
초기 MVP 기준:

| 데이터 | 소스 |
| :--- | :--- |
| 급등주 후보 | Yahoo Finance |
| OHLCV | Yahoo Finance |
| 섹터 ETF | Yahoo Finance |
| RVOL 계산 | Yahoo Finance |

---

# 3.2 보조 데이터 소스
| 데이터 | 소스 |
| :--- | :--- |
| 추가 종목 정보 | Finnhub |
| 기업 정보 | Finnhub |
| 시가총액 | Finnhub |

---

# 3.3 한국투자증권(KIS) 역할
현재 MRH에서 KIS는:

```
자동 주문 API
```
용도가 아니다.

역할:

```
보조 가격 검증
+
미래 확장 가능성 확보
```
정도.

---

# 제4장. 왜 Yahoo Finance 기반인가

# 4.1 핵심 이유
MRH 핵심은:

```
초고정밀 기관 데이터
```
가 아니다.

실제로 필요한 건:

```
매일 장 마감 후
강한 종목 후보 확인
```
이다.

---

# 4.2 Yahoo Finance 장점
| 장점 | 설명 |
| :--- | :--- |
| 무료 | MVP 적합 |
| 안정성 | 충분히 높음 |
| OHLCV 제공 | 가능 |
| 미국 주식 광범위 지원 | 가능 |
| 구현 단순 | 매우 중요 |

---

# 4.3 단점 인정
| 단점 | 영향 |
| :--- | :--- |
| 딜레이 존재 | 존재 |
| 실시간 부정확 | 존재 |
| 간헐적 오류 | 존재 |

하지만 MRH는:

```
일봉 기반 단기 swing 시스템
```
이므로 치명적이지 않음.

---

# 제5장. 실제 수집 대상

# 5.1 핵심 유니버스
MRH는:

```
미국 전체 시장
```
을 스캔하지 않는다.

---

# 5.2 실제 수집 대상
매일:

```
급등 후보 30~100개
```
정도만 수집.

---

# 5.3 이유
핵심은:

```
이미 강한 종목 중
추가 continuation 가능성 탐색
```
이기 때문.

---

# 제6장. 실제 후보 수집 규칙

# 6.1 기본 조건
| 조건 | 기준 |
| :--- | :--- |
| 하루 상승률 | +5% 이상 |
| 거래량 증가 | RVOL > 1.5 |
| 가격 | $5 이상 |
| 시총 | 대형주 우선 |

---

# 6.2 제외 조건
| 조건 | 이유 |
| :--- | :--- |
| 초저유동성 | 위험 |
| penny stock | 제외 |
| 거래정지 | 제외 |
| ETF | 후보 제외 |

---

# 제7장. 데이터 수집 시간

# 7.1 핵심 시간
MRH는:

```
미국 장 마감 후
1회 수집
```
원칙.

---

# 7.2 실제 배치 시간
예시:

```
한국 시간 오전 6:00
```

---

# 제8장. 수집 데이터 구조

# 8.1 실제 필드
| 필드 | 설명 |
| :--- | :--- |
| ticker | 티커 |
| open | 시가 |
| high | 고가 |
| low | 저가 |
| close | 종가 |
| volume | 거래량 |
| daily_change_pct | 상승률 |
| sector | 섹터 |

---

# 제9장. Relative Volume 계산

# 9.1 계산 구조

```
오늘 거래량
÷
20일 평균 거래량
```

---

# 9.2 핵심 기준

```
RVOL > 2
```
강한 자금 유입으로 판단.

---

# 제10장. 데이터 Normalize 규칙

# 10.1 핵심 목적
외부 데이터는:

```
형식이 제각각
```
이다.

따라서 내부 표준화 필요.

---

# 10.2 Normalize 구조
| 항목 | 규칙 |
| :--- | :--- |
| ticker | 대문자 |
| volume | bigint |
| 가격 | float |
| 날짜 | UTC 통일 |

---

# 제11장. Data Validation

# 11.1 Validation 목적

```
잘못된 급등 데이터 차단
```

---

# 11.2 검증 조건
| 조건 | 행동 |
| :--- | :--- |
| volume = 0 | 폐기 |
| close <= 0 | 폐기 |
| NaN 발생 | 폐기 |
| duplicate | 제거 |

---

# 제12장. SAFE MODE

# 12.1 목적
무료 API 장애 대응.

---

# 12.2 SAFE MODE 발동
| 조건 | 행동 |
| :--- | :--- |
| Yahoo 장애 | fallback |
| 2일 이상 실패 | SAFE MODE |
| 데이터 누락률 > 5% | batch 중단 |

---

# 12.3 SAFE MODE 행동

```
신규 BUY 금지
+
기존 포지션만 관리
```

---

# 13.2 저장 파일

# 제14장. MVP에서 하지 않는 것
초기 MVP 제외:

- 실시간 websocket
- tick data
- orderbook
- options chain
- high frequency feed
- nanosecond execution

---

# 제15장. External Ingestion 시스템의 진짜 역할
MRH Ingestion 시스템은:

```
기관급 초고속 데이터 시스템
```
이 아니다.

핵심은:

```
매일 장 마감 후

강한 후보를 안정적으로 수집하고
내부 필터로 재정렬하는 것
```
이다.
