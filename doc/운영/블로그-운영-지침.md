# 1부 규칙

## 0. 한눈에 — 지켜야 할 12가지

1. **빈 글은 올리지 않는다.** 이벤트 · 신호가 없는 날은 건너뛰고, 내용 없는 섹션은 "없다" 문장 대신 통째로 뺀다.
2. **스팸 기준은 편수가 아니라 비슷함이다.** 같은 뼈대의 얇은 글을 늘리지 않는다.
3. **새 글 · 새 페이지는 하루에 조금씩.** 새 고정 페이지는 실행 한 번에 10개(`NEW_PAGES_PER_RUN`), API 호출 사이 4초 이상.
4. **테스트 글을 공개로 올리지 않는다.** 확인은 비공개 초안(`--draft`)으로. 새 리포트 첫 발행은 `테스트 중` 라벨.
5. **Gemini는 키 하나 · 프로젝트 하나.** 한도를 늘리려고 키 · 프로젝트 · 계정을 나누지 않는다(약관상 사용량 제한 우회).
6. **새 기능은 Groq · NVIDIA를 먼저, Gemini는 예비.** Gemini 하루 한도는 모든 리포트가 나눠 쓰는 공용 예산이다.
7. **AI가 쓴 칸은 AI라고 표시한다.** 모델명과 함께. 사람 이름을 AI 글에 붙이지 않는다.
8. **기사 본문은 저장하지도 옮기지도 않는다.** 제목 · 출처 · 시각 · 링크 · 분류 결과만 저장한다.
9. **글의 중심은 우리 데이터다.** 기사에서는 사실(누가 · 언제 · 무엇을)만 가져오고, 문장 · 해석 · 숫자는 우리 것으로 쓴다.
10. **매수 · 매도 권유 · 이익 보장 · 개인 맞춤 판단 금지.** 과거 기록은 조건 · 표본 수와 함께.
11. **기록은 지우지 않는다.** 다시 모을 수 없는 자료는 상태 브랜치에 쌓고, 잘라내기 전에 보관한다.
12. **키 · 토큰은 어디에도 출력하지 않는다.** 채팅 · 터미널 · 로그 · 문서 모두. 마스킹한 값도 남기지 않는다.

## 1. 스팸 · 검색 품질

근거: [종목-레이더-기획.md 6절](../기획/종목-레이더-기획.md#6-스팸--검색-품질--글-수가-아니라-비슷함)

### 1-1. 누가 무엇을 보나

| 판별 주체 | 보는 것 | 걸리면 |
|---|---|---|
| Blogger 자동 탐지 | 게시 속도 · API 자동 게시 패턴 · 글끼리 얼마나 비슷한가 · 링크 · 계정 이력 | 블로그 잠금(스팸 판정) — 블로그 전체가 멈춘다. 검토 요청 없이 약 3개월 지나면 영구 삭제 경고(2026-08 사례, D9) |
| 구글 검색 (대량 생성 콘텐츠 남용 정책, 2024-03~) | 사람 · AI 무관. 검색 노출을 노려 대량으로 찍은 비슷한 글인가, 고유한 가치가 있나 | 검색 순위 하락 · 색인 제외 · 수동 조치 |
| 애드센스 | 가치를 더하지 않은 자동 생성 콘텐츠 | 광고 제한 · 승인 거절 |

판별 주체는 사람이 썼는지 AI가 썼는지 구분하지 못한다. **보는 것은 글의 내용과 조합이 새로운가**다. "사람이 검수했다"는 그 자체로 효과가 없고, 검수로 글이 서로 달라지는 만큼만 효과가 있다.

### 1-2. 규칙

- **빈 글 금지** — 이벤트 0건인 날 · 휴장일 · 데이터 수집 실패 날은 발행하지 않는다. "오늘은 특별한 일이 없었다"만 있는 글이 가장 위험하다.
- **빈 섹션 생략** — 고정 문장("오늘 주제에서는 … 없다")을 넣지 말고 섹션을 뺀다. 안내가 꼭 필요하면 `MISSING_HINTS` 처럼 한 줄로.
- **템플릿 복제 경계** — 종목 · 인물마다 같은 틀로 글을 찍지 않는다. 같은 틀이면 숫자만 다른 글이 된다. 종목이 늘면 **개별 글이 아니라 레이더 한 편 + 조건을 넘은 종목만 개별 글**(하루 3편 상한)로 간다.
- **해석이 있는 칸** — "관찰됐다" 정리만 있는 글은 얇다. 리포트를 가로지르는 관전평처럼 **입장 · 이유 · 틀렸다고 볼 조건**이 있는 칸이 글을 다르게 만든다.
- **남이 못 베끼는 값이 글의 뼈대** — 시장 상태 점수 · 플라시보 검정을 거친 반응 통계 · 이벤트 신규성 · 섹터 대비 등락 · 이슈 저장소의 "과거 n번, 그 뒤 분포".
- **링크** — 본문 링크는 출처(1차 자료 · 기사 원문)와 우리 글 사이 링크만. 링크 교환 · 대량 외부 링크 · 같은 링크 반복을 넣지 않는다.
- **제목** — 같은 리포트는 날짜로만 구별되는 제목이 매일 쌓이는 구조다. 제목에 그날의 핵심(가장 큰 이벤트 · 숫자)을 넣을 수 있으면 넣는다(검색 노출 규칙은 8절).

## 2. 발행량 · 블로거 쓰기 한도

근거: [종목-레이더-기획.md](../기획/종목-레이더-기획.md) 1 · 10절, `experiments/stock-radar/publish_pages.py`, `universe.py`

### 2-1. 공식 기준과 실측

| 항목 | 값 | 출처 |
|---|---|---|
| 하루 글 수 공식 한도 | **공개된 숫자 없음.** "하루 한 자리 수"는 경험칙 | 1절 — 기준은 비슷함 |
| Blogger API 하루 할당량 | 프로젝트당 **10,000 Queries/일** (기본값). 갱신(PUT)도 같은 "Queries" 지표로 센다 | D9 |
| 고정 페이지 수 | **한도 없음** (Blogger 도움말 answer/165955, 10-18 확인) | 종목-레이더 10절 |
| API 버스트 | 1초 간격이면 **6번째부터 429**, 새 페이지 20개 중 10개 실패 (2026-10-18 실측) | publish_pages.py |
| 글당 라벨 수 | 확인 안 함 — 라벨을 많이 달 일이 생기면 먼저 확인 | 종목-레이더 열린 결정 |

### 2-2. 규칙

- **새 고정 페이지는 실행 한 번에 `NEW_PAGES_PER_RUN`(지금 10)개까지.** 나머지는 다음 날. 만들다 실패한 것도 센다.
- **API 호출 사이 4초 이상.** 429를 받으면 기다렸다 다시(백오프). 한 페이지가 백오프 끝까지 실패하면 그 실행의 **나머지 쓰기는 멈추고** 다음 실행으로 넘긴다.
- **개별 글은 10분 간격.** 레이더 뒤 개별 리포트를 이어 올릴 때.
- **하루 새 글은 한 자리 수 안에서.** 2-3 표의 합계를 먼저 센다.
- **기존 글 · 페이지 갱신(PUT)도 쓰기다.** 같은 간격을 지키고, **바뀐 것이 없는 페이지는 다시 쓰지 않는다**(내용 해시 비교).
- **테스트는 초안으로.** `publish.py --draft` 처럼 비공개 초안을 만들고 폰에서 Blogger 미리보기로 확인한다. 공개 테스트 글은 올렸다 지워도 스팸 신호로 남는다.
- **새 리포트 첫 발행은 `테스트 중` 라벨** (`config.TEST_MODE`). 테스트 기간은 **2~4주**로 정하고 끝나면 False — 제목은 바뀌지 않는다.
- **게시 확인은 검색이 아니라 API로.** `check_published.py` 는 최근 15건만 본다 — 하루 글이 15건을 넘는 구조가 되면 고친다.

### 2-3. 지금 자동 실행 (2026-10-21)

| 워크플로 | 설계 주기 (UTC) | 실제 (D7-1) | 블로그에 쓰는 것 |
|---|---|---|---|
| `test-daily-report.yml` | 평일 22:00 · 23:30 + Cloudflare Worker 뉴욕 17:00 · 18:30 | 하루 1편 (중복 확인으로 막음) | 데일리 리포트 글 1편 |

## 3. AI 사용 — 약관 · 한도 · 표시

근거: `experiments/llm_chain.py` 머리말, [개발-구현-기록-현황.md](../../개발-구현-기록-현황.md) 9.1~9.3, [종목-레이더-기획.md](../기획/종목-레이더-기획.md) 1 · 10절

### 3-1. 돌려 쓰기 금지 (약관)

- **Gemini는 키 하나 · 프로젝트 하나.** `GEMINI_API_KEY` 에 키가 여럿 들어 있어도 `gemini_keys()` 는 첫 키만 쓴다(2026-10-19 고침).
- **하지 않는 것**: 같은 공급자의 키 · 프로젝트 · Google 계정 · GitHub 계정을 늘려 무료 한도를 합치는 것. 약관상 사용량 제한 우회이고, 계정 단위로 막힌 사례가 있다. 차단은 계정이 아니라 IP · 요청량 기준이라 효과도 없다.
- **해도 되는 것**: **다른 회사**의 무료 API(Groq · NVIDIA 등)를 사슬로 잇는 것 — 별개 서비스라 우회가 아니다. 로컬 모델. 한도가 정말 모자라면 같은 프로젝트를 **유료 등급**으로 올리는 것.
- **같은 규칙이 시세 API 에도 적용된다** (2026-10-21): Polygon · Twelve Data · Finnhub · Alpha Vantage 도 공급자마다 **키 하나**. `price_source._key` 는 쉼표 목록이 와도 첫 키만 쓴다.
- 2026-10-14 ~ 10-18 에는 다른 프로젝트의 키 5개를 돌려 썼다 — 지금은 쓰지 않는다. 옛 실측 수치를 근거로 "키를 늘리자"는 계획을 세우지 않는다.

### 3-2. 공용 예산으로 아껴 쓰기

- Gemini 하루 한도는 **프로젝트 × 모델** 단위(`GenerateRequestsPerDayPerProjectPerModel`)이고 모든 리포트가 나눠 쓴다. 3.5-flash 는 실측 하루 약 20회(503 재시도도 횟수에 든다), flash-lite 는 버킷이 따로라 훨씬 많다.
- **새 기능 설계 순서**: ① 파이썬 틀로 쓸 수 있나(숫자 · 고정 문장) ② Groq · NVIDIA 로 되나 ③ flash-lite ④ 마지막에 flash. 분류는 lite, 서술만 flash.
- 공급자 · 순서를 바꾸는 곳은 `llm_chain.py` 의 `STEPS` · `CHAINS` 하나. 새 공급자는 **실제 프롬프트로 정확도를 비교한 뒤에만** 넣는다.
- 하루 한도(PerDay)를 받으면 그 실행 동안 그 모델을 버린다 — 재시도로 한도를 태우지 않는다.

### 3-3. 각 공급자 약관에서 볼 것

| 확인할 것 | 왜 |
|---|---|
| 무료 등급을 **공개 서비스(운영)** 에 써도 되나 | 일부 무료 엔드포인트는 시험 · 개발용으로만 허락한다 |
| 무료 등급 입력이 **모델 학습에 쓰이나** | 쓰인다면 독자 댓글 · 개인 정보 · 비공개 자료를 보내지 않는다 |
| 출력물을 **광고가 붙은 글**에 써도 되나 | 상업적 이용 조건 |
| 생성 이미지의 이용 조건 | 커버 이미지 |

공급자별 확인 결과는 **D3-2 표**에 둔다(2026-10-21 조사). 새 공급자를 넣을 때 그 표에 줄을 더한다.

### 3-4. AI가 쓴 것 표시 · 검사

- AI가 쓴 칸에는 **"AI 관전평 · gemini-3.5-flash" 처럼 모델명**을 적는다. 예비 모델이 답하면 그 모델명(`pool.last_model`).
- 사람 메모는 사람 이름 + 시각으로 따로. **사용자 이름을 AI 글에 붙이지 않는다** — 독자 신뢰.
- 공통 푸터에 AI 가 하는 일(분류 · 해설 문장 · 번역 · 커버 이미지)을 밝힌다.
- **숫자는 AI가 만들지 않는다.** 숫자는 파이썬이 계산하고, AI 문장 속 숫자는 표에 있는 것만 — `fact_check` 로 대조, 어긋나면 다음 단계로.
- AI 지시문에 늘 넣는 금지: 매수 · 매도 권유, 확정 예측("오를 것"), 원인 단정, 입력에 없는 사실.
- 예비 · 대체 모델 글은 방향 오류가 잦았다(10-15 · 10-16) — 알림으로 사람이 볼 수 있게 한다.

## 4. 수집 기사 · 저작권 — 기사 + 우리 자료로 재해석

근거: [알파-종목-리포트-기획.md](../기획/알파-종목-리포트-기획.md) 저장 범위 · 쓰지 않는 소스, [엔비디아-리포트-기획.md](../기획/엔비디아-리포트-기획.md) 소스 선택, `fetch_news.py`

### 4-1. 법의 큰 줄기 (공개 자료 정리)

| 근거 | 뜻 | 우리에게 |
|---|---|---|
| 저작권법 제7조 5호 | **사실의 전달에 불과한 시사보도**는 보호받지 못한다 | 사건 자체(누가 언제 무엇을 발표했다 · 숫자)는 누구나 쓸 수 있다. 보호되는 것은 기자의 **표현**(문장 · 구성 · 해설 · 사진) |
| 제28조 공표된 저작물의 인용 | 보도 · 비평 · 교육 · 연구를 위해 **정당한 범위 · 공정한 관행**으로 인용 가능 | 우리 글이 주(主), 인용이 종(從). 짧게, 따옴표로, 출처와 함께 |
| 제35조의5 공정한 이용 | 이용 목적 · 성격, 저작물 종류, 이용 비중, **원 시장 대체 여부**를 따진다 | 우리 글을 읽으면 원 기사를 안 읽어도 되는 수준이면 위험 |
| 제37조 출처 명시 | 인용할 때 출처를 밝힌다 | 매체명 + 원문 링크 — **화면에 보이는 글자로** |
| 번역 = 2차적 저작물 (제5조) | 남의 기사를 통째로 번역하면 복제와 같다 | 외신 본문 · 요약문 번역 게시는 조심 (4-5) |
| 미국 Fair Use (17 U.S.C. §107) · DMCA | 미국 매체(CNBC 등) · Blogger(Google)는 미국 기준. 신고가 오면 DMCA 절차로 글이 내려간다 | 같은 원칙(변형적 이용 · 소량 · 시장 대체 없음) |

### 4-2. 저장 규칙

- **저장하는 것**: 제목 · 매체 · 시각 · 링크 · 우리 분류 결과(주제 · 방향 · 강도 · 대상 종목) · 우리가 뽑은 짧은 인용(인물 발언).
- **저장하지 않는 것**: 기사 본문 · 기사 이미지 · 유료 기사 내용. 저작권과 용량 둘 다의 이유다.
- **공개 저장소 · 공개 브랜치에 올리는 것은 "배포"다.** 저장소가 PUBLIC 이므로 gh-pages · 상태 브랜치의 파일도 공개 배포물이다. 매체의 요약문 원문은 공개 브랜치에 두지 않는다(로컬 · 비공개 보관만).
- **수집하지 않는 것**: 뉴스 본문 크롤링 · X(트위터) · Reddit 스크래핑(약관 위반) · 유료벽(paywall) 우회 · 로그인이 필요한 페이지.
- 수집 빈도는 낮게(하루 1회 ~ 2시간 1회), 요청 사이 간격을 둔다. 사이트가 막으면(Cloudflare 등) 우회하지 않고 2차 소스로 간다.

### 4-3. 재해석 방식 — 우리 글을 쓰는 법

기사는 **재료(사실의 출처)**, 우리 데이터가 **본문**이다.

| 단계 | 할 일 | 하지 않는 일 |
|---|---|---|
| ① 사실만 뽑기 | 누가 · 언제 · 무엇을 · 숫자(발표치 · 예상치) | 기자의 해설 · 전망 · 비유 · 문장 구성 |
| ② 우리 데이터 붙이기 | 이 이슈가 이슈 저장소의 어느 종류인가 · 과거 같은 종류 n번 뒤 분포 · 오늘 시장 상태 점수 · 섹터 대비 등락 · 이벤트 신규성 | 기사 숫자를 우리 숫자처럼 쓰기 |
| ③ 우리 문장으로 쓰기 | 우리 구성 · 우리 표 · 우리 해석(관전평: 입장 · 이유 · 틀렸다고 볼 조건) | 기사 문단 순서대로 바꿔 쓰기(패러프레이즈 나열) |
| ④ 출처 달기 | 사실마다 매체명 + 원문 링크. 1차 자료(공시 · 보도자료 · 관보 · 법원)가 있으면 그쪽을 먼저 | 출처 없이 "알려졌다". 매체명을 툴팁에만 숨기기 |

**점검 질문** — 발행 전에 하나라도 "예"면 고친다.
- 이 글에서 우리 데이터 · 우리 해석을 빼면 남는 게 기사 요약뿐인가?
- 우리 글만 읽으면 원 기사를 읽을 필요가 없어지나?
- 한 기사에서 가져온 문장이 2~3문장을 넘나? (직접 인용은 한두 문장, 따옴표)
- 기사 사진 · 그래프 · 표를 그대로 썼나?
- **AI 서술이 실패했을 때 영문 원문(제목 · 요약)이 그대로 나가는 경로가 있나?**

### 4-4. 1차 자료 우선

- 공시(SEC EDGAR) · 회사 뉴스룸 · 보도자료 · 연방관보 · 법원 문서 · 연준 · 백악관 · USTR 발표는 **1차 자료**다. 미국 연방정부 저작물은 공유 영역(17 U.S.C. §105)이고, 회사 보도자료는 배포 목적이라 인용이 쉽다. 가능하면 이쪽을 출처로 단다.
- 외부 기사가 1차 자료를 다시 옮긴 것(`repeat`)이면 기사 대신 1차 자료를 쓴다(NVDA 파이프라인 방식).
- **인물 발언**: 발언 자체는 짧게 따옴표로 인용하고, 그 발언을 전한 기사 · 원 게시물을 **매체명과 함께** 출처로 단다. 발언을 해설한 기사(해설 · 분석)는 버린다.
- **유료 뉴스레터(Substack 등)** 는 공개 RSS 분량만 쓰고 본문을 요약 게시하지 않는다.

### 4-5. 홈 뉴스 — 점검할 곳

- 홈 뉴스는 CNBC RSS 의 **제목을 번역**하고, **RSS 요약을 옮긴 한 줄 소개(s)** 와 **선정 이유 한 문장(why)** 을 붙인다. 본문은 가져오지도 옮기지도 않는다.
- 제목 · 한 줄 소개는 짧고 원문 링크로 보내므로 "기사로 안내하는" 성격이다. 그래도 RSS 요약도 매체의 표현이므로 **요약을 길게 · 통째로 옮기지 않는다** — 소개는 **코드 상한 120자**, 여러 줄로 만들지 않는다.
- 클릭하면 반드시 원문으로 간다. 홈에서 기사를 대신 읽게 만드는 구조(펼치면 요약 여러 문단)는 만들지 않는다.

### 4-6. 이미지

- 기사 · 뉴스 사이트 · 다른 블로그의 이미지는 쓰지 않는다.
- 커버는 생성 이미지(D3-2 약관) 또는 우리가 그린 차트. 차트는 우리 데이터로 우리가 그린 것만. 생성 이미지에는 "AI 생성 이미지" 표시.
- **종목 로고는 식별 용도로만 쓴다**(2026-10-22 사용자 결정, 10-21 "로고 금지"를 바꿈 — 로고는 신뢰도). 조건:
  - 우리 gh-pages `images/logos/` 사본만. 제3자 사이트 핫링크 금지(그 사이트의 약관 · 가용성에 묶인다).
  - 출처를 고정해 받고 기록한다: `experiments/fetch_ticker_logos.py` → `experiments/ref/ticker_logos.json` (MrChartist/global-stock-logos 고정 커밋, 출처 기록 없는 파일은 받지 않는다).
  - 원래 모양 그대로, 티커 · 종목명 옆 작은 크기(20~32px)만. 커버 · 제목 장식 · 우리 브랜드 근처에는 쓰지 않는다.
  - 없는 종목(ETF 등) · 삭제 요청이 온 종목은 티커 두 글자 배지 (`REMOVED` 에 넣고 다시 받는다).
  - 블로그 공통 푸터에 상표 고지("각 회사의 상표 · 식별 용도 · 제휴 없음").
- 그 밖의 로고(회사 · 매체 · 서비스 로고를 꾸밈으로 쓰는 것)는 쓰지 않는다.
- **인물 사진은 공직자(+기관)만** 쓴다(2026-10-21 사용자 결정, 인물 발언 레이더): 정부 공식 사진 · 공공 영역 · 자유 라이선스만, 우리 gh-pages 에 복사해 쓴다(핫링크 금지). 민간인(투자자 · CEO · 방송인)은 초상권 · 퍼블리시티권 때문에 글자 동그라미. 저작자 표시가 필요한 라이선스는 쓰지 않는다.

## 5. 금융 법적 경계

근거: [리포트-법적-경계.md](../리포트-재설계/리포트-법적-경계.md) — 한국 법령 기준(2026-10-17 사용자 결정), 미국은 참고

지금 구조(**무료 · 광고수익만 · 모두에게 같은 글 · 정기 발행**)에서는 투자자문업 · 유사투자자문업 신고 · 등록 대상이 아니다. 넘으면 안 되는 선:

1. **대가** — 유료 구독 · 멤버십 · 유료 리포트를 붙이면 유사투자자문업 신고. 유료 + 양방향(댓글 · 채팅)이면 투자자문업 등록.
2. **개별성** — 댓글 · AI 답글에서 "당신은 지금 팔아라 / 사라" 같은 개인 맞춤 판단 금지.
3. **이해관계** — 보유를 알리지 않는 대신 **매수 추천을 하지 않는다**(선 4가 안전장치).
4. **표현** — 이익 보장 · 목표 수익률 · 매수 권유 문구 금지. 과거 기록은 "과거에 ~였다 · 국면 n개"처럼 조건 · 표본과 함께. n < 30 묶음의 숫자 · 단일 사례를 오늘에 대입하지 않는다.

면책 문구는 공통 푸터에 둔다. 유료화 · 상담 기능 · 광고 규모가 크게 바뀌면 금융위 법령해석 포털에 개별 질의한다.

## 7. 댓글 · 독자와 주고받기

- 댓글은 우리 것(Firebase · Google 로그인). AI 자동 답글은 **개인 맞춤 매수 · 매도 판단을 거절**하도록 지시문에 고정(5절 선 2). 지시문을 고칠 때 질문 3개로 다시 확인한다.
- 독자 댓글 · 개인 정보를 무료 AI 등급에 보낼 때 D3-2 의 학습 이용 조건을 본다. 이메일 · 이름은 보내지 않는다.
- 스팸 댓글 · 광고 링크 댓글은 답글하지 않고 숨긴다. AI 답글에 외부 링크를 넣지 않는다.
- 사람 메모(편집자 메모)는 주인 UID 만 쓸 수 있다. 쓰지 않은 날은 흔적을 남기지 않는다("메모 없음" 금지).
- 쓰기 남용 방어(사용자별 횟수 · App Check)가 없으면 댓글 쓰기는 "로그인한 누구나 무제한"이다 — D7-4.

## 8. 사이트 문구 · 검색 노출

- **블로그 설명 · 검색 설명 · 사이트 공통 문구에는 특정 종목명을 넣지 않는다** — "종목별"로 일반화. 검색 설명은 150바이트 안.
- 검색엔진이 먼저 읽는 곳만 고친다: 제목 검색어 · 맨 앞 요약(`p[data-seo-lead]`) · 글 제목 h1 · 함께 보는 리포트(`div[data-related]`). 본문 구조는 유지(현황 9.7).
- 숨긴 텍스트 · 키워드 나열 · 제목과 다른 내용(낚시 제목)은 쓰지 않는다 — 검색 스팸 정책 위반.
- 영문 주소는 영문 제목으로 게시한 뒤 한글 제목으로 바꾸는 방식(시험 확인됨).
- **크롤러가 따라갈 수 있는 길**을 둔다: 홈 → 글, 글 → 글, 종목 페이지 → 종목 페이지. `/search/label/…` 는 Blogger 기본 robots 가 막으므로 링크 경로로 치지 않는다.

## 9. 보안 · 비밀 값

- API 키 · OAuth 토큰 · 서비스 계정은 GitHub 시크릿과 로컬 `.env` 에만. **채팅 · 터미널 출력 · 로그 · 문서 · 커밋에 값을 출력하지 않는다** — 일부만 보이게 가린 값도 남기지 않는다. 확인이 필요하면 "있다 / 없다 · 길이"까지만.
- **저장소가 PUBLIC 이므로 Actions 로그 · artifact 도 공개다.** 키가 URL 쿼리에 들어가는 호출은 예외 메시지를 통째로 출력하지 않는다(URL 이 포함된다).
- `.env` 는 커밋하지 않는다(`.gitignore`). 실수로 올라가면 이력에서 지우는 것보다 **키 재발급이 먼저**.
- 결과물(리포트 · 문서 · 페이지)은 외부 공유 서비스에 올리지 않고 로컬 파일 · 저장소로만 만든다.
- 워크플로 로그에 요청 헤더 · 응답 전체를 찍지 않는다.
