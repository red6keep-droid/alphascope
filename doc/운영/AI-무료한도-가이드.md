# 무료 AI 모델 한도 가이드 (Gemini · Groq)

다른 프로젝트의 AI 에이전트에게 주는 문서다. 목적은 하나: **쉬운 일에 고급 모델을 쓰다가 하루 한도가 바닥나는 일을 막는 것.**
숫자는 2026-10-28 Google AI Studio 할당량 화면과 Groq 오류 원문(429)에서 실측한 무료 등급 값이다.
계정 · 프로젝트 · 시점마다 다를 수 있으니, **작업 전 자기 프로젝트의 할당량 화면을 한 번 확인**하고 다르면 그 값을 따른다.

---

## 1. 한도 표 (무료 등급)

### Google Gemini (AI Studio API 키)

| 모델 | 하루 요청 (RPD) | 분당 요청 (RPM) | 분당 토큰 (TPM) | 성격 |
|---|---|---|---|---|
| **gemini-3.6-flash** (고급) | **20회** | 5회 | 25만 | 글 품질 최고. **하루 20회뿐 — 아껴야 하는 자원** |
| **gemini-3.5-flash-lite** (가벼움) | **500회** | 15회 | 25만 | 분류 · 요약 · 추출에 충분. 긴 서술은 다소 두루뭉술 |
| gemini-3-flash-preview | 20회 | 5회 | — | 미리보기 모델, 응답이 자주 깨져 비추천 |
| gemini-3.1-flash-lite | 500회 | 15회 | — | lite 대체 후보 |

- 한도는 **프로젝트 × 모델** 단위다. 모델마다 따로 센다.
- **초기화 시각: 미국 태평양 자정** = 한국 시간 오후 4시(서머타임) / 오후 5시(겨울).
- **503 과부하**(구글 서버 사정)가 하루에 여러 번 올 수 있다. 503 재시도도 하루 횟수에 드는 것으로 보인다 → 재시도는 2회까지만.
- 하루 20회짜리 flash 는 재시도 몇 번만 해도 금방 바닥난다. 실제로 우리 쪽은 하루 28회가 필요한 날이 있어 모자랐다.

### Groq (무료 키 하나로 여러 모델, 한도는 모델마다 따로)

| 모델 | 하루 요청 | **하루 토큰 (TPD)** | 분당 토큰 (TPM, 입력+출력) | 분당 출력 (OTPM) |
|---|---|---|---|---|
| openai/gpt-oss-120b | 1,000 | **20만** | 8,000 | 실측에서 안 걸림 |
| Qwen 3.8 27B | 1,000 | **20만** | 8,000 | **1,000** |

- **하루 요청 1,000회보다 하루 토큰 20만이 먼저 찬다.** 호출당 5천 ~ 8천 토큰이면 하루 25 ~ 40회가 실제 한계.
- **요청 하나가 8,000토큰을 넘으면 413 `Request too large`** — 몇 번을 보내도 거절. 긴 프롬프트는 Groq 에 못 보낸다.
- Qwen 은 **호출당 출력 1,000토큰 이하**여야 받힌다(`max_completion_tokens` 를 1,000 이하로). 넘으면 쉬어도 계속 거절.
- 같은 모델 연속 호출은 **60초 간격**을 두면 분당 한도에 잘 안 걸린다.
- 빠르다(5 ~ 6초). 다만 숫자 방향을 뒤집는 사실 오류가 있었다 → 숫자가 들어간 글은 원문 숫자와 대조.

## 2. 일 → 모델 고르기 (핵심 규칙)

**원칙: 가장 싼 모델부터. 고급 모델(flash, 하루 20회)은 "독자에게 나가는 긴 글"에만.**

| 일의 종류 | 1순위 | 예비 | 고급 flash 쓰나? |
|---|---|---|---|
| 분류 · 태그 · 예/아니오 판정 | Groq (gpt-oss / Qwen) | flash-lite | **쓰지 않는다** |
| 짧은 요약 · 번역 · 제목 정리 | Groq | flash-lite | 쓰지 않는다 |
| JSON 추출 (출력 짧음) | Groq Qwen | gpt-oss → flash-lite | 쓰지 않는다 |
| 출력이 1,000토큰 넘는 일 | Groq gpt-oss | flash-lite | 쓰지 않는다 |
| 프롬프트가 8,000토큰 넘는 일 | flash-lite | — | 품질이 꼭 필요할 때만 |
| 사람이 읽는 긴 서술 · 리포트 본문 | **flash** | flash-lite | **여기에만** |
| 코드 생성 · 테스트 · 개발 중 시험 호출 | flash-lite 또는 Groq | — | **쓰지 않는다** (시험에 20회를 다 쓰는 일이 가장 흔한 사고) |

새 기능을 만들 때는 **먼저 하루 사용량을 계산**한다: `하루 호출 수 × 호출당 (입력 + 출력) 토큰`.
이 값이 위 표의 하루 한도 안에 드는지 확인하고, 안 들면 배치 크기 · 호출 수 · 입력 길이를 줄인다.

## 3. 오류가 났을 때

| 오류 | 뜻 | 할 일 |
|---|---|---|
| Gemini 429 + `PerDay` (`GenerateRequestsPerDayPerProjectPerModel`) | 오늘 그 모델 끝 | **즉시 포기**, 재시도 금지. 그 실행 동안 그 모델 건너뛰고 다음 모델로 |
| Gemini 429 + `PerMinute` | 분당 한도 | 60초 쉬고 1회 재시도 |
| Gemini 503 | 구글 서버 과부하 | 3초 · 6초 뒤 재시도 2회까지, 그래도 안 되면 다음 모델(lite) |
| Groq 429 `tokens per minute (TPM)` … `try again in 23.5s` | 분당 한도 | 알려 준 시간(`retry-after`)만큼 기다렸다 1회 더 |
| Groq 429 `output tokens per minute (OTPM)` | Qwen 출력 한도 | 기다려도 잘 안 풀림 → 바로 다음 모델. 출력 상한을 1,000 이하로 고친다 |
| Groq 429 `tokens per day (TPD)` | 오늘 그 모델 끝 | 즉시 포기, 그 실행 동안 건너뜀 |
| Groq 413 `Request too large` | 요청 하나가 8,000토큰 초과 | 재시도 무의미. 입력을 쪼개거나 Gemini 로 |
| JSON 깨짐 (`Expecting property name …`) | 모델 출력 형식 | 다음 모델로 (같은 모델 반복 재시도는 한도만 씀) |

**절대 하지 말 것: 하루 한도 오류에 재시도 루프 돌리기.** 이것이 한도를 순식간에 바닥내는 주범이다.

## 4. 예비 사슬 구조 (권장)

모델 하나에 의존하지 말고 순서대로 넘기는 사슬을 둔다.

```
가벼운 일:  Groq Qwen → Groq gpt-oss → gemini-flash-lite
긴 글:      gemini-flash → gemini-flash-lite → (Groq 는 프롬프트 8K 이하일 때만)
```

- 각 단계가 실패하면(한도 · 과부하 · 형식 오류) 다음 단계로.
- 하루 한도로 실패한 모델은 **그 실행이 끝날 때까지 기억해 두고 건너뛴다**.
- 어떤 모델이 답했는지 기록해 둔다 — 예비 모델이 만든 결과는 나중에 고급 모델로 다시 처리할 수 있게.
- 전부 실패하면 프로그램이 죽지 않게 대체 처리(원문 그대로 표시 · 다음 실행으로 미루기)를 둔다.

## 5. 약관 · 보안

- **Gemini API 키는 하나만 쓴다.** 한도를 늘리려고 키 · 프로젝트를 여러 개 돌려 쓰는 것은 약관 위반이다. 모자라면 유료 등급을 쓰거나 호출을 줄인다.
- 키 값은 로그 · 화면 · 커밋에 절대 출력하지 않는다. 환경 변수(`.env`, CI secret)로만.
- 남은 양 확인: Gemini 는 AI Studio 할당량 화면, Groq 는 응답 헤더 `x-ratelimit-remaining-requests`(하루 토큰은 헤더에 없고 429 문구 `Used N` 으로만 보인다).
