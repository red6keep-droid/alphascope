# 데일리 리포트 파이프라인

매 거래일 아침, 세 곳에서 데이터를 긁어와 Gemini에게 문장을 맡기고, 표는 파이썬이 직접 그려
블로그에 올린다. 숫자와 문장의 담당을 갈라놓은 것이 이 파이프라인의 전부이자 핵심이다.

이 문서는 두 부분이다. **1부**는 지금 돌고 있는 파이프라인을 코드 기준으로 설명한다.
**2부**는 다음 단계 — 수집과 Gemini 사이에 **파이썬 분석 계층**을 끼워 "오늘 어땠나"를 설명하는
브리핑에서 "어제와 무엇이 달라졌고, 내일 무엇을 봐야 하나"를 보여주는 리포트로 바꾸는 설계다.

| 항목 | 지금 | 목표 |
| --- | --- | --- |
| 실행 | 화~토 06:00 KST (월~금 21:00 UTC) · 재시도 07:30 KST | 동일 |
| 데이터 소스 | FRED · Yahoo Finance · CNBC | + 섹터 ETF · 금리 · 시장 폭 (새 키 불필요) |
| 파이썬 계산 | 등락률, 표 포맷 | + 1D/5D/20D · 연속성 · 현재 위치 · 시장 폭 · Regime Score · 섹터 로테이션 · 상태판 |
| LLM 담당 | 문장 9개 | 문장 ~14개 + 뉴스 ↔ 자산 연결 · 내일 체크 항목의 "이유" |
| 중단 지점 | 5개 — 하나라도 걸리면 미게시 | 동일 + 새 출력의 구조 검증 |
| 산출물 | Blogger 글 1건 + jsDelivr 커버 이미지 | + `report-state` 브랜치의 일별 분석 이력 |

```
지금:   수집 → Gemini → 검증 → 커버 이미지 → HTML 렌더 → 게시
         01     02       03      04           05          06

목표:   수집 → 분석(파이썬) → Gemini → 검증 → 커버 이미지 → HTML 렌더 → 게시 → 이력 저장
         01     01.5           02       03      04           05          06     07
```

# 1부 — 지금 돌고 있는 것

## 설계 원칙 — 숫자는 파이썬이, 문장은 Gemini가

LLM에게 숫자를 맡기면 언젠가 틀린 숫자를 자신 있게 쓴다. 그래서 이 파이프라인은 역할을 물리적으로
갈라놨다. Gemini는 **표를 만들지 않고, 숫자를 입력하지 않고, 뉴스를 지어내지 않는다.**
수집한 원본에서 표를 그리는 것은 `render_html.py`이고, Gemini가 내놓는 것은 해설 문장과
"몇 번째 뉴스를 고를지"라는 인덱스뿐이다.

**Gemini가 만드는 것**

- 시장 요약 · 분위기 · 종합 의견 · 위험요인
- 급등주 / 관심종목 해설 문구
- 경제지표 해설
- 뉴스 `index` 선택과 선정 이유
- 커버 이미지용 영문 프롬프트

**파이썬이 만드는 것**

- 지수 · 급등주 · 관심종목 · 경제지표 표 전부
- 가격 · 등락률 · 거래량 포맷과 색상
- 뉴스 제목과 링크 (선택된 index로 원본에서 꺼냄)
- 게시글 제목, 날짜, 면책 문구
- 커버 이미지 태그와 CDN URL

이 분리 덕분에 Gemini가 헛소리를 해도 *숫자는* 틀리지 않는다. 대신 뉴스 index가 범위를 벗어나는
식의 오류는 발생할 수 있어서, 다음 단계인 검증이 그것만 집중해서 잡는다.
2부의 확장은 이 원칙을 **그대로 두고** 파이썬이 계산하는 숫자의 종류만 늘리는 것이다.

## 01. 수집 — 세 곳에서 긁어온다

> `collect_fred.py` · `collect_yahoo.py` · `collect_news.py`

세 수집기가 차례로 돌고, 결과가 `output/report_input.json` 하나로 합쳐진다.
날짜는 **KST 기준**이라 미국 장 마감 다음 날 아침 파일이 만들어진다.

### FRED — 미국 경제지표 3종

세인트루이스 연은의 `series/observations` 엔드포인트를 시리즈별로 호출한다.
최신순 8개 관측치를 받아 **값이 `.`(결측)이 아닌 첫 항목**을 채택하는데,
FRED가 발표 예정일 행을 먼저 비워둔 채 내려주기 때문이다.

| 지표 | 시리즈 ID | 받는 값 | 비고 |
| --- | --- | --- | --- |
| 실업률 | `UNRATE` | 값 + 기준일 | 월간 발표 |
| 소비자물가 | `CPIAUCSL` | 값 + 기준일 | 지수값 그대로 (전년비 아님) |
| 변동성지수 | `VIXCLS` | 값 + 기준일 | 일간 종가 |

- 소수점 둘째 자리 반올림, `{value, date}` 형태로 저장
- 네트워크 오류는 해당 지표만 `null`로 두고 나머지는 계속 진행 — 다만 검증에서 걸린다
- 키: `FRED_API_KEY`

### Yahoo Finance — 지수 5종과 종목 10개

지수는 `yfinance`의 `fast_info`에서 현재가와 전일 종가를 받는다. **당일 스냅샷 한 점**이고,
과거 시계열은 받지 않는다 — 2부에서 바꾸는 지점이 바로 여기다.
홈 화면용 `fetch_stocks.py`와는 별개 모듈이고, 여기서는 VIX가 지수 목록에 포함된다.

| 구분 | 심볼 | `report_input.json` 키 |
| --- | --- | --- |
| S&P 500 | `^GSPC` | `sp500` |
| 나스닥 | `^IXIC` | `nasdaq` |
| 다우존스 | `^DJI` | `dow` |
| 러셀 2000 | `^RUT` | `russell` |
| VIX | `^VIX` | `vix` |

- 각 지수마다 가격 · 등락률 · 거래량을 담는다
- 등락률은 받아오지 않고 `(현재가 − 전일종가) ÷ 전일종가 × 100`으로 직접 계산한다
- 수집에 실패한 지수는 가격이 `null`로 남고, 검증 단계에서 걸린다

급등주와 관심종목은 Yahoo의 비공식 스크리너 API를 먼저 두드린다. 요청 전에
`fc.yahoo.com`에 한 번 GET을 보내 쿠키를 받아두는데, 이게 없으면 스크리너가 자주 막힌다.

| 목록 | `scrIds` | 후보 | 필터 | 최종 |
| --- | --- | --- | --- | --- |
| 오늘의 급등주 | `day_gainers` | 10 | 가격 ≥ $1, 거래량 ≥ 1,000,000 | 등락률 내림차순 **TOP 5** |
| 시장 관심 종목 | `most_actives` | 10 | 동일 | 거래량 내림차순 **TOP 5** |

스크리너가 실패하면 곧바로 대체 경로로 넘어간다. 대형주 **50종목 고정 유니버스**를
`yf.download(period="2d", interval="1d")`로 한 번에 받아 전일 종가 대비 등락률을 직접 계산한 뒤,
같은 필터와 정렬을 적용한다. 실제 시장 전체의 급등주는 아니지만, 그날 리포트가 통째로 비는 것보다
낫다는 판단이다.

### CNBC — 뉴스 후보 20건

CNBC의 RSS를 파싱한다. Gemini가 3~5건을 *고르게* 하려면 후보가 넉넉해야 해서
홈 화면용(`fetch_news.py`, 12건)보다 많은 20건을 담는다.

| 단계 | 처리 |
| --- | --- |
| 가져오기 | `cnbc.com/id/15839069/device/rss/rss.html` |
| 정제 | CDATA 벗기기 → HTML 엔티티 복원 → 요약문 태그 제거 후 공백 정규화 |
| 제외 | 링크에 `cnbc.com`이 없는 항목 · 제목이 섹션명(`Investing`, `Top News`, `Tech` 등 13개)인 항목 · 제목 15자 미만 · 링크 중복 |
| 정규화 | 발행시각 RFC 822 → `YYYY-MM-DD HH:MM:SS` · 요약문 300자 컷 |
| 결과 | 최대 20건, 각각 `title` / `source` / `link` / `published` / `summary` |

### 합쳐진 입력 파일

```jsonc
// output/report_input.json
{
  "date":        "2026-09-04",              // KST 기준 오늘
  "updated_at":  "2026-09-03 21:05:00 UTC",
  "macro":       { unemployment_rate, cpi, vix },
  "market":      { indices: { sp500, nasdaq, dow, russell, vix } },
  "gainers":     [ 5건 ],
  "most_active": [ 5건 ],
  "news":        [ 최대 20건 ]
}
```

## 02. Gemini 작성 — 문장만 받아온다

> `generate_report.py` · `prompts/daily_report.txt`

프롬프트 본문 뒤에 방금 만든 JSON을 통째로 붙여 한 번에 보낸다.
응답은 `response_mime_type="application/json"`으로 강제하고, 그래도 코드펜스가 붙어 오는 경우가 있어
` ```json `을 벗겨낸 뒤 첫 `{`부터 마지막 `}`까지를 잘라 파싱한다.

### 모델과 키 로테이션

- 기본 모델 `gemini-3.5-flash` — `GEMINI_MODEL`로 교체 가능
- `GEMINI_API_KEY`에 세미콜론이나 쉼표로 여러 키를 넣으면 순서대로 시도한다
- 키마다 **2회**씩, 실패 사이에 2초 대기. 키를 모두 소진하면 예외를 던지고 파이프라인이 죽는다
- 로그에는 키가 `AIzaSyAL***` 형태로만 찍힌다

### 프롬프트가 못 박아둔 규칙

1. 제공되지 않은 숫자를 만들지 말 것. 숫자는 본문에 쓰지 말고 분석 문구로만 쓸 것 — 표는 파이썬이 그린다.
2. 뉴스는 제공된 목록의 `index`로만 고를 것. 목록에 없는 뉴스를 지어내지 말 것.
3. 데이터가 없으면 추측하지 말고 "데이터 없음"이라고 쓸 것.
4. 뉴스에 없는 내용을 사실처럼 덧붙이지 말 것.
5. 매수·매도를 권유하지 말 것. 객관적으로 설명할 것.
6. 불확실한 정보는 아예 언급하지 말 것.
7. 종목 심볼은 데이터에 있는 대문자 표기 그대로 쓸 것.
8. `image_prompt`는 영문 한 문장, 200자 이내. 숫자·문자가 그림에 나오지 않게 할 것.
   **하락장이어도 폭풍·침몰 같은 어두운 소재를 피하고** 밝은 비유로 쓸 것.

### 돌려받는 11개 키

| 키 | 내용 | 리포트에서 놓이는 자리 |
| --- | --- | --- |
| `summary` | 증시 전체 요약 3~5문장 | 오늘의 시장 요약 |
| `change_comment` | 1D/5D/20D · 연속성 · 레인지 위치 · 상대강도가 말하는 변화 2~3문장 (1단계 추가) | 무엇이 달라졌나 |
| `market_mood` | VIX·지수 방향성 기반 분위기 | 시장 분위기 |
| `sector_comment` | 주도/약세 섹터와 로테이션 2~3문장 (4단계 추가) | 섹터 · 테마 |
| `gainers_comment` | 급등주 해설 | 급등주 표 아래 |
| `attention_comment` | 거래량 상위 종목 해설 | 관심종목 표 아래 |
| `news[]` | `{ index, why, theme, related[] }` 3~5개 — `theme`은 어휘 8개 중, `related`는 `symbols` 목록 안에서 0~3개 (4단계 추가) | 주요 뉴스 목록 |
| `macro_comment` | 금리(10Y 방향 · 스프레드 · `growth_label`) + 실업률·CPI·VIX 해설 (4단계에서 확장) | 금리 · 경제지표 표 아래 |
| `opinion` | 종합 의견 2~3문장 | 종합 의견 |
| `risk` | 위험요인 2~5개 (줄바꿈 구분) | 주의할 위험요인 |
| `image_prompt` | 커버 생성용 영문 문장 | 본문에는 안 나감 |

> **중단** — 모든 API 키가 실패하면 예외가 발생하고 파이프라인이 종료된다. 그날 리포트는 없다.

## 03. 검증 — 여기서 걸리면 안 올라간다

> `validate_report.py`

수집 데이터와 Gemini 출력을 같이 본다. 핵심은 **오류와 경고를 나눈 것**이다.
지표가 비면 리포트의 의미가 없으니 멈추지만, 급등주 목록이 비는 건 "데이터 없음"으로 표기하고 넘어간다.

**오류 — 게시 중단 (`exit 1`)**

- 경제지표 3종 중 하나라도 결측
- 지수 5종 중 하나라도 가격이 `null`
- Gemini 필수 키 9개 중 누락되거나 빈 문자열
- `image_prompt`가 300자 초과
- 뉴스 `index`가 정수가 아니거나 0~19 범위 밖

**경고 — 로그만 남기고 진행**

- 급등주 목록이 비어 있음
- 관심종목 목록이 비어 있음
- 선정된 뉴스가 3~5건이 아님

뉴스 index 검사가 특히 중요하다. 범위를 벗어난 index를 그냥 두면 렌더 단계에서 조용히 건너뛰어
"주요 뉴스"가 텅 빈 채로 게시될 수 있기 때문이다.

> **중단** — 오류가 하나라도 있으면 항목을 전부 출력하고 `exit 1`. 이미지 생성 비용도 쓰지 않는다.

## 04. 커버 이미지 — 공짜 경로부터

> `generate_image.py`

Gemini가 준 `image_prompt` 뒤에 고정 스타일 접미사를 붙여 이미지를 만든다.
매일 톤이 튀지 않게 하려는 장치이고, 문구는 이렇다.

```
bright cheerful flat vector illustration, vibrant colorful modern
editorial art style, absolutely no photorealism, no photographs,
no text, no numbers, no letters
```

| 순서 | 공급자 | 키 | 재시도 |
| --- | --- | --- | --- |
| 1 | Pollinations.ai (`flux` → `turbo`) | 불필요 | 모델당 2회, 3초 간격 (타임아웃 90초) |
| 2 | Hugging Face `FLUX.1-schnell` | `HF_TOKEN` | 1회 — 여기서만 `negative_prompt`를 함께 보낸다 |

- 크기 **1024 × 400** — 글 상단에 얹는 와이드 배너 비율
- 응답이 진짜 이미지인지 확인한다: 10KB 이상이면서 JPEG · PNG · WebP 매직 바이트로 시작할 것
- Pillow로 **WebP quality 80** 변환 후 `output/images/{date}.webp`에 저장

**왜 GitHub에 올리나** — Blogger API는 이미지 업로드를 지원하지 않는다.
그래서 워크플로우가 이미지를 `gh-pages` 브랜치에 배포하고, 본문에는 jsDelivr CDN 주소를 박는다.

```
https://cdn.jsdelivr.net/gh/red6keep-droid/alphascope@gh-pages/images/{date}.webp
```

> **중단** — 두 공급자 모두 실패하면 게시 실행에서는 `exit 1`.
> dry-run이면 경고만 남기고 계속 진행한다.

## 05. HTML 렌더 — 표를 그리는 자리

> `render_html.py` · `templates/report.html`

템플릿에 뚫린 **마커 15개**를 채워 본문을 완성한다. Blogger 본문에는 외부 CSS를 붙일 수 없어
모든 스타일이 인라인으로 들어간다. 표 4개는 전부 이 단계에서 *수집 원본을 직접 읽어* 만들어진다.

| --- | --- | --- |

## 06. 게시 — 이미지가 살아 있을 때만

> `publish_saved.py` · `publish_blogger.py` · `check_published.py`

로컬에서는 `main.py --publish`가 바로 올리지만, GitHub Actions에서는
**항상 dry-run으로 돌린 뒤 따로 게시한다.** 커버 이미지를 gh-pages에 배포하고
CDN에 실제로 떴는지 확인한 다음 글을 올려야, 독자가 첫 화면에서 깨진 이미지를 보지 않기 때문이다.

### 게시 전 통과해야 하는 조건

| 확인 | 실패하면 |
| --- | --- |
| `title.txt` · `report_body.html` · `image_ref.txt` 존재 | `exit 1` |
| 제목과 본문이 비어 있지 않음 | `exit 1` |
| `image_ref.txt`가 비어 있지 않음 | `exit 1` |
| jsDelivr 커버 URL에 `HEAD` 요청 → 200 | `exit 1` |
| 같은 제목의 글이 아직 없음 | 건너뜀 (오류 아님) |

### Blogger 인증

- OAuth 2.0 데스크톱 클라이언트로 **한 번** 브라우저 승인 → refresh token 발급 (`setup_oauth.py`)
- 이후 실행은 refresh token으로 액세스 토큰을 자동 갱신 — 사람 개입 없음
- 블로그 URL로 `blogs/byurl`을 호출해 blogId를 얻고, 그 blogId에 글을 POST
- 라벨 고정: `데일리 브리핑` / `미국 증시` / `자동 리포트`

### 중복 게시를 막는 이중 방어

GitHub의 cron은 부하가 높으면 조용히 누락된다. 실제로 2026년 8월 27일 스케줄이 실행되지 않았고,
8월 28일은 21:00 UTC 예정이 02:26 UTC로 5시간 넘게 밀렸다.
그래서 cron을 하루 두 번 걸고, 대신 같은 날 두 번 올라가지 않도록 두 겹으로 막는다.

| 단계 | 하는 일 | 효과 |
| --- | --- | --- |
| `check_published.py` | 워크플로우 맨 앞에서 오늘 제목의 글을 조회 → `already_published` 출력 | 이미 있으면 이후 단계 전부 skip. Gemini 호출과 이미지 생성 비용을 아낀다 |
| `publish_saved.py` | 게시 직전에 최근 15건의 제목을 다시 비교 | 확인 실패나 두 실행이 겹치는 경우를 잡는 2차 방어 |

확인 자체가 실패하면 **"게시되지 않았다"로 간주하고 진행**한다.
중복 한 건이 그날 리포트가 통째로 누락되는 것보다 낫다는 판단이고, 어차피 2차 방어가 남아 있다.

> 알아둘 것: `check_published.py`는 최근 **15건**만 조회한다. 하루 1건씩이면 문제없지만,
> 다른 글을 자주 올리면 그날 리포트가 15건 밖으로 밀려 중복 감지가 뚫릴 수 있다.

# 2부 — 다음 단계: 분석 계층

## 왜 바꾸나 — 스냅샷은 투자 판단에 부족하다

지금 리포트에 들어가는 숫자는 전부 **당일 한 점**이다. 지수 5개의 오늘 등락률, 급등주 5개, 거래량
상위 5개, 경제지표 3개. 여기에 뉴스 5건을 붙이면 "오늘 미국 증시가 어땠는가"는 잘 설명된다.

하지만 투자자가 매일 읽을 이유가 되는 것은 절대값이 아니라 **변화**다.

> S&P 500 +0.8%

보다

> S&P 500 3일 연속 상승, 20일 고점 −0.3%. VIX 18.2 → 16.4.
> Nasdaq의 상승폭이 4일 연속 S&P 500을 웃돌고, 10년물 금리는 5일간 −12bp.

가 정보 가치가 훨씬 높다. 그리고 이 문장의 숫자는 **전부 파이썬이 계산할 수 있다.** Gemini에게는
"왜 이런 상태인가"만 물으면 된다.

현재 구조에서 빠져 있는 것을 다섯 가지로 정리하면:

| 빠진 것 | 지금 | 있으면 |
| --- | --- | --- |
| **변화 추적** | 1D 등락률만 | 1D / 5D / 20D, 연속 상승·하락, 20일 고저점 대비 위치 |
| **시장 상태 점수** | `market_mood` 문장 | 규칙으로 계산한 Regime Score(0~100)와 그 구성 요소 |
| **시장 폭** | 지수만 | 상승/하락 종목 수, 신고가/신저가, 50일선 위 비율 |
| **섹터 · 테마** | 개별 종목 10개 | 섹터 ETF 11개의 1D/5D/20D → 오늘의 주도 섹터 |
| **금리** | 없음 | 10Y · 2Y · 스프레드, 그리고 금리 ↔ 성장주 방향의 관계 |

여기에 리포트의 끝을 **"내일 확인할 것"**으로 바꾸면, 오늘을 설명하는 문서에서 내일을 준비하는
문서가 된다.

## 바뀌는 구조 — 수집과 Gemini 사이에 한 단계

```
                  ┌─ FRED     (경제지표 + 금리)
                  ├─ Yahoo    (지수 · 종목 · ETF, 이번엔 3개월 시계열)
                  ├─ CNBC     (뉴스 20건)
                  └─ 이력     (report-state 브랜치의 어제까지 analysis)
                       ↓
               report_input.json                      ← 원본. 지금과 같은 파일
                       ↓
          ┌────────────────────────┐
          │      analyze.py        │
          │                        │
          │  1D / 5D / 20D 수익률  │
          │  연속성 · 현재 위치    │
          │  상대강도              │
          │  시장 폭               │
          │  섹터 로테이션         │
          │  금리 ↔ 성장주         │
          │  Regime Score          │
          │  상태판 · 내일 체크    │
          └───────────┬────────────┘
                      ↓
                analysis.json                          ← 새 파일. 계산 결과 + 원본
                      ↓
                   Gemini                              ← "왜 이런 상태인가"
                      ↓
                   검증                                 ← 구조 + 일관성
                      ↓
              커버 이미지 → HTML → Blogger
                      ↓
              analysis.json 을 이력에 추가
```

원칙은 하나만 기억하면 된다. **점수·등급·추세·레벨은 전부 파이썬이 만들고, Gemini는 그것을
받아서 설명한다.** Gemini가 72점을 만들어서는 안 된다. `regime_score = 72`는 `analyze.py`가
쓰고, Gemini는 "72라는 결과가 왜 나왔는지"를 문장으로 옮긴다.

## A. 수집 확장 — ETF · 금리 · 시장 폭

새 API 키는 하나도 필요 없다. Yahoo는 그대로 무료이고, FRED는 이미 키가 있다.

### Yahoo — 스냅샷에서 시계열로

> 구현됨 — `collect_yahoo.collect_history()` · `HISTORY_UNIVERSE`

`fast_info` 스냅샷 옆에 `yf.download(period="6mo", interval="1d")` 호출을 하나 더 둔다.
한 번의 호출로 아래 유니버스 전체의 종가 120여 개씩을 받아 **`output/prices.json`에 따로** 저장한다 —
`report_input.json`에 섞으면 Gemini 입력이 80KB 늘어나기 때문이다.
**1D/5D/20D · 연속성 · 이동평균 · 고저점은 이 데이터만으로 전부 계산되므로 별도 저장소가 필요 없다.**

지수의 당일 가격·등락률은 여전히 `fast_info`에서 받는다. 게시되는 표의 숫자 소스를 바꾸지 않기
위해서고, 대신 `analyze.py`가 시계열의 마지막 종가와 `fast_info` 가격을 비교해 0.1% 넘게 다르면
`history_stale`을 켠다 — 시계열에 오늘 바가 아직 안 붙었다는 뜻이다. 날짜로 비교하면 주말·휴장에
오탐이 나서 가격으로 본다.

심볼마다 마지막 행 날짜가 다를 수 있다. `^VIX`는 다음 거래일 부분 바가 먼저 붙는다. 그래서
`^GSPC`의 마지막 종가 날짜를 **기준일(`as_of`)**로 잡고 모든 시계열을 거기까지로 자른다.

| 그룹 | 심볼 | 용도 |
| --- | --- | --- |
| 지수 | `^GSPC` `^IXIC` `^DJI` `^RUT` `^VIX` | 지금과 동일 — 변화 추적·연속성·위치의 대상. `^GSPC`가 기준일 앵커 |
| 광의 시장 | `SPY` `QQQ` `IWM` `RSP` | 상대강도 (QQQ−SPY, IWM−SPY), 동일가중 `RSP`−`SPY`는 시장 폭 프록시 |
| 섹터 ETF | `XLK` `XLF` `XLE` `XLV` `XLP` `XLY` `XLU` `XLI` `XLB` `XLRE` `XLC` | 섹터 로테이션 · 오늘의 주도 섹터 |
| 테마 | `SMH` | 반도체 — AI 테마의 가격 반응 |
| 금리 · 안전자산 | `TLT` `HYG` `GLD` | 위험선호 판단, 금리 ↔ 성장주 연결 |
| 금리 (당일) | `^TNX` `^FVX` `^IRX` | 10Y · 5Y · 3M 수익률. FRED보다 하루 빠르다 |

- 급등주 · 관심종목 수집(스크리너 → 50종목 fallback)은 그대로 둔다
- `updated_at`과 등락률 계산 규칙도 그대로. 지수 `price`/`change_pct`는 시계열의 마지막 두 행에서 뽑는다
- 심볼별로 결측 행이 있으면 그 심볼만 `null`. 지수 5종 결측은 여전히 검증 오류, ETF 결측은 경고

### FRED — 금리 4종 추가

> 구현됨 — `collect_fred.SERIES`에 `us10y` `us2y` `spread_10_2` `fed_funds`

`collect_fred.SERIES` 딕셔너리에 네 줄을 더했다. 호출 방식 · 결측 처리 · 반올림 규칙은 기존과 같다.
`validate_report.REQUIRED_MACRO`에는 넣지 않는다 — 금리가 결측이어도 리포트는 나가야 한다.

| 지표 | 시리즈 ID | 비고 |
| --- | --- | --- |
| 10년물 국채금리 | `DGS10` | 일간. **전 영업일 값**으로 내려오는 날이 많아 당일 값은 `^TNX`를 쓴다 |
| 2년물 국채금리 | `DGS2` | 일간 |
| 10Y−2Y 스프레드 | `T10Y2Y` | 일간. 음수면 역전 |
| 연방기금금리 | `DFF` | 일간 실효금리 |

기존 3종(`UNRATE` `CPIAUCSL` `VIXCLS`)은 그대로다. FRED의 VIX는 검증용으로 남기고,
리포트에서 쓰는 VIX 시계열은 Yahoo `^VIX`로 통일한다 — 5일 변화를 같은 소스에서 계산하기 위해서다.

### 시장 폭 — 프록시부터, 전수는 나중에

Yahoo에는 상승/하락 종목 수를 바로 주는 엔드포인트가 없다. 두 단계로 간다.

| 단계 | 방법 | 얻는 것 | 비용 |
| --- | --- | --- | --- |
| **프록시** | 위 유니버스에서 계산 | 섹터 ETF 11개 중 상승 개수 · `RSP`−`SPY` 1D/5D | 추가 호출 0 |
| **전수** | S&P 500 구성종목 `yf.download(period="1y")` | 상승/하락 수 · 52주 신고가/신저가 수 · 50일선 위 비율 | 약 500심볼 × 1년, 1~3분 |

전수 방식의 구성종목 목록은 리포에 **정적 파일**(`data/sp500_constituents.txt`)로 두고 분기마다
손으로 갱신한다. Wikipedia를 매일 긁는 방식은 페이지 구조가 바뀌면 그날 리포트가 죽기 때문이다.
다운로드 커버리지가 90% 미만이면 전수 결과를 버리고 프록시로 떨어진다. 어느 쪽을 썼는지는
`analysis.json`의 `breadth.mode`에 남긴다.

## B. 분석 — analyze.py가 계산하는 것

> 구현됨 — `analyze.py`. 입력 `report_input.json` + `prices.json` + `state/regime.jsonl`, 출력 `analysis.json`
> · `state/history/{date}.json` · `state/regime.jsonl`

이 파일에는 **LLM 호출이 없다.** 순수 파이썬 산술이고, 같은 입력이면 항상 같은 출력이다.
아래 규칙의 숫자(임계값 · 배점)는 초기값이다. 그림자 모드로 2~3주 이력을 쌓은 뒤 조정한다
(→ [도입 순서](#도입-순서--다섯-단계-그림자-모드부터)).

### B-1. 변화 추적 — 1D / 5D / 20D

지수 5종 · 광의 시장 4종 · 섹터 ETF 11종 · `SMH` `TLT` `HYG` `GLD` 전부에 대해:

| 값 | 계산 |
| --- | --- |
| `ret_1d` `ret_5d` `ret_20d` | `close[-1] / close[-1-n] − 1`, 백분율 소수 둘째 자리 |
| `ma20` `ma50` | 단순이동평균. 50일선은 `period="3mo"` 로 충분치 않으면 `6mo` |
| `above_ma20` `above_ma50` | 불리언 |
| `ma20_slope` | `ma20[-1] − ma20[-5]` 의 부호 |

VIX는 수익률 대신 **레벨 변화**로 쓴다: `vix_now`, `vix_5d_ago`, `vix_change_5d`.

### B-2. 연속성 — 며칠 연속인가

| 값 | 계산 |
| --- | --- |
| `streak` | 마지막 날 방향과 같은 방향이 연속된 일수. 부호 = 방향 (`+4` 4일 연속 상승, `−2` 2일 연속 하락) |
| `last5` | 최근 5거래일 방향 배열 `["↑","↑","↑","↑","↓"]` — 렌더가 그대로 찍는다 |
| `up_days_20` `down_days_20` | 최근 20거래일 중 상승/하락 일수 |

### B-3. 현재 위치 — 고점 가까이인가

지수 4종(VIX 제외)과 `SPY` `QQQ` `IWM`에 대해:

| 값 | 계산 |
| --- | --- |
| `high_20d` `low_20d` | 20거래일 종가 최고/최저 |
| `from_high_pct` `from_low_pct` | `(close / high_20d − 1) × 100`, `(close / low_20d − 1) × 100` |
| `position_label` | 규칙 → 라벨. 아래 표 |

| 조건 | 라벨 |
| --- | --- |
| `from_high_pct > −1` 이고 `ret_20d > +5` | **단기 고점 부근 · 과열 주의** |
| `from_high_pct > −1` | **20일 고점 부근** |
| `from_low_pct < +1` | **20일 저점 부근** |
| 그 외 | **박스 중간** |

"추격 매수 위험" 같은 판단을 Gemini의 감각에 맡기지 않고 이 라벨로 고정하는 것이 목적이다.

### B-4. 상대강도 — 어디로 돈이 가나

| 값 | 계산 | 읽는 법 |
| --- | --- | --- |
| `rs_qqq_spy_5d` | `QQQ.ret_5d − SPY.ret_5d` | 양수면 성장주 우위 |
| `rs_iwm_spy_5d` | `IWM.ret_5d − SPY.ret_5d` | 양수면 소형주(위험선호) 우위 |
| `rs_rsp_spy_5d` | `RSP.ret_5d − SPY.ret_5d` | 양수면 상승이 넓게 퍼짐 (시장 폭 프록시) |
| `rs_streak_qqq` | `QQQ.ret_1d > SPY.ret_1d` 가 연속된 일수 | "Nasdaq 상승폭이 4일 연속 S&P 500 상회" |

### B-5. 시장 폭

프록시 모드:

| 값 | 계산 |
| --- | --- |
| `sectors_up` `sectors_down` | 섹터 ETF 11개 중 `ret_1d ≥ 0` / `< 0` 개수 |
| `breadth_ratio` | `sectors_up / 11 × 100` |
| `rsp_spy_1d` `rsp_spy_5d` | 동일가중 − 시가총액가중 |

전수 모드에서는 `sectors_*` 대신 `advancers` `decliners` `new_high_52w` `new_low_52w` `pct_above_ma50`이
들어가고 `breadth_ratio = advancers / (advancers + decliners) × 100`이다.

| `breadth_ratio` | 라벨 |
| --- | --- |
| ≥ 65 | 🟢 양호 — 넓게 참여 |
| 45 ~ 65 | 🟡 보통 |
| < 45 | 🔴 취약 — 소수 종목이 지수를 끌어올림 |

지수가 +1.2%인데 라벨이 🔴이면 그 자체가 리포트의 핵심 문장이 된다.

### B-6. 섹터 로테이션 · 오늘의 테마

섹터 ETF 11개 + `SMH`를 `ret_1d` 내림차순으로 정렬한다. 상위 3개가 **오늘의 주도 섹터**,
하위 3개가 **오늘의 약한 섹터**. `ret_5d` 순위와 비교해 "5일 순위에서 몇 계단 올랐는지"도 남긴다.

테마는 ETF에 고정으로 매핑한다. Gemini가 테마를 발명하지 않게 하기 위해서다.

| 테마 | ETF |
| --- | --- |
| AI / 반도체 | `SMH` |
| 기술 | `XLK` |
| 금융 | `XLF` |
| 에너지 | `XLE` |
| 헬스케어 | `XLV` |
| 소비 (경기민감) | `XLY` |
| 소비 (필수) | `XLP` |
| 유틸리티 | `XLU` |
| 산업 | `XLI` |
| 소재 | `XLB` |
| 리츠 | `XLRE` |
| 통신 | `XLC` |

렌더는 이 순위를 막대 그래프로 그린다 — 인라인 스타일 `div`의 `width`만 바꾸면 되므로 Blogger에서도 동작한다.

### B-7. 금리 ↔ 성장주

| 값 | 계산 |
| --- | --- |
| `us10y` `us2y` `spread_10_2` | `^TNX` 당일값, FRED `DGS2`, `T10Y2Y` |
| `us10y_change_1d_bp` `us10y_change_5d_bp` | `^TNX` 시계열, bp 단위 |
| `rates_growth_label` | 아래 규칙 |

| 10Y 5D 변화 | `QQQ.ret_5d` | 라벨 |
| --- | --- | --- |
| ≥ +10bp | < 0 | **금리 상승이 성장주에 부담** |
| ≤ −10bp | > 0 | **금리 하락과 성장주 강세 동반** |
| ≥ +10bp | > 0 | **금리 상승에도 성장주 견조** (성장 기대 우위) |
| 그 외 | — | **금리 영향 중립** |

### B-8. Regime Score — 시장 상태 점수

다섯 요소의 합, 0~100. 각 요소는 위에서 계산한 값에 대한 구간 규칙이다.

| 요소 | 배점 | 규칙 |
| --- | --- | --- |
| **추세** | 25 | `SPY.above_ma20` +10 · `SPY.above_ma50` +10 · `SPY.ma20_slope > 0` +5 |
| **시장 폭** | 20 | `breadth_ratio` ≥ 70 → 20 · 55~70 → 14 · 45~55 → 8 · < 45 → 0 |
| **변동성** | 20 | `vix_now` < 15 → 20 · 15~20 → 14 · 20~25 → 8 · 25~30 → 3 · ≥ 30 → 0, `vix_change_5d < −2` 이면 +2 (상한 20) |
| **금리 환경** | 15 | `us10y_change_5d_bp` ≤ −10 → 15 · −10~0 → 11 · 0~+10 → 6 · > +10 → 0 |
| **위험선호** | 20 | `rs_qqq_spy_5d > 0` +5 · `rs_iwm_spy_5d > 0` +5 · `SPY.ret_5d − TLT.ret_5d > 0` +5 · `HYG.ret_5d > 0` +5 |

| 점수 | `regime.label` |
| --- | --- |
| ≥ 70 | **Risk-On** 🟢 |
| 45 ~ 69 | **Neutral** 🟡 |
| < 45 | **Risk-Off** 🔴 |

`regime.score_prev`(어제 점수)와 `regime.delta`는 **이력에서** 읽는다. 이력이 없는 첫날은 `null`.
이것이 이력 저장이 필요한 유일한 이유다 — 가격에서 다시 계산할 수 없는 값은 우리가 만든 점수뿐이다.

렌더는 이렇게 그린다.

```
MARKET REGIME                    🟢 Risk-On   72 / 100   (어제 68, +4)

추세          ████████████████████████░  25 / 25
시장 폭       ████████████████░░░░░░░░░  14 / 20
변동성        ████████████████░░░░░░░░░  14 / 20
금리 환경     ████████████░░░░░░░░░░░░░   8 / 15
위험선호      ███████████░░░░░░░░░░░░░░  11 / 20
```

### B-9. 상태판 — 행동이 아니라 환경을 보여준다

리포트는 "NVDA를 매수해야 합니다"라고 쓰지 않는다. 프롬프트 규칙 5가 이미 그렇게 막고 있다.
대신 **투자 환경을 신호등으로 표시**하고, 판단은 독자에게 남긴다. 이것도 규칙이다.

| 항목 | 🟢 | 🟡 | 🔴 |
| --- | --- | --- | --- |
| 추세 유지 | `SPY` 20일선·50일선 위 | 하나만 위 | 둘 다 아래 |
| 변동성 | `vix_now` < 18 | 18 ~ 25 | > 25 |
| 시장 폭 | `breadth_ratio` ≥ 55 | 45 ~ 55 | < 45 |
| 금리 리스크 | 10Y 5D ≤ +5bp | +5 ~ +15bp | > +15bp |
| 과열 위험 | 그 외 | `SPY.ret_20d` ≥ +4 | `SPY.ret_20d` ≥ +6 이고 `from_high_pct > −0.5` |

`overall`은 🔴가 하나라도 있으면 🔴, 🟡가 둘 이상이면 🟡, 아니면 🟢.

### B-10. 내일 체크할 것 — 후보는 파이썬이, 이유는 Gemini가

레벨은 전부 계산값이다. `analyze.py`가 아래 규칙으로 **후보를 만들고 우선순위대로 5개**를 고른다.
Gemini는 각 항목의 `id`를 받아 한 문장 `why`만 붙인다.

| `id` | 조건 (후보에 오르는 때) | 지켜볼 레벨 |
| --- | --- | --- |
| `spx_high` | `from_high_pct > −2` | `high_20d` 돌파 여부 |
| `spx_low` | `from_low_pct < +2` | `low_20d` 이탈 여부 — 레인지가 좁아 둘 다 해당하면 가까운 쪽 하나만 |
| `spx_ma20` | 20일선과 거리 < 1% | 20일선 회복/이탈 |
| `vix_20` / `vix_25` | `vix_now`가 임계값 ±3 이내 | 20 / 25 상향 돌파 여부 |
| `us10y_level` | 항상 | 가장 가까운 0.1% 단위 라운드 레벨 상향 여부 |
| `breadth_50` | `breadth_ratio` 40~60 | 상승 비율 50% 유지 여부 |
| `leader_rs` | 주도 섹터 1위가 5D에서도 1~3위 | 상대강도 유지 여부 |
| `regime_flip` | `regime.score`가 경계(45/70) ±5 이내 | 등급 전환 여부 |

우선순위는 표 순서다. 렌더는 `metric` · `level` · `direction`을 파이썬 값으로 찍고 `why`만 Gemini 문장을 쓴다.

### analysis.json

```jsonc
{
  "date": "2026-09-15",
  "raw":       { /* report_input.json 그대로. macro · indices · gainers · most_active · news */ },
  "series":    { "SPY": { ret_1d, ret_5d, ret_20d, ma20, ma50, above_ma20, above_ma50, ma20_slope,
                          streak, last5, up_days_20, down_days_20 }, "QQQ": {...}, "XLK": {...}, ... },
  "position":  { "sp500": { high_20d, low_20d, from_high_pct, from_low_pct, position_label }, ... },
  "vix":       { now, prev_5d, change_5d },
  "rs":        { qqq_spy_5d, iwm_spy_5d, rsp_spy_5d, qqq_streak },
  "breadth":   { mode: "proxy" | "full", ratio, label, ... },
  "sectors":   { ranked_1d: [ { etf, theme, ret_1d, ret_5d, rank_5d } ], leaders: [...], laggards: [...] },
  "rates":     { us10y, us2y, spread_10_2, us10y_change_1d_bp, us10y_change_5d_bp, growth_label },
  "regime":    { score, label, components: { trend, breadth, volatility, rates, risk_appetite },
                 score_prev, delta },
  "status":    { trend, volatility, breadth, rates, overheat, overall },
  "watch":     [ { id, metric, level, direction } ],           // 5개, why는 아직 없음
  "symbols":   [ "SPY", "QQQ", ..., "NVDA", ... ]             // Gemini가 related에 쓸 수 있는 전체 목록
}
```

`raw`를 통째로 넣는 이유는 Gemini에 보낼 파일을 **이 하나로** 끝내기 위해서다. 검증과 렌더도 이 파일만 읽는다.

## C. Gemini의 새 역할 — 숫자를 설명하고, 뉴스를 자산에 연결한다

> `prompts/daily_report.txt` 개정 · `generate_report.py`의 입력을 `analysis.json`으로

기존 규칙 8개는 그대로 두고 두 개를 더한다.

9. **점수 · 등급 · 라벨은 `analysis.json`의 값을 그대로 따를 것.** `regime.label`이 Risk-Off인데
   "위험선호가 강화"라고 쓰지 말 것. 반대 해석은 오류다.
10. 뉴스마다 `theme`은 아래 목록에서, `related`는 `symbols` 목록에서만 고를 것.
    목록에 없는 심볼이나 테마를 쓰지 말 것.

`theme` 어휘: `금리` · `AI/반도체` · `실적` · `매크로` · `에너지` · `정책/규제` · `지정학` · `기타`

### 돌려받는 키

기존 9개 중 `market_mood`는 `regime_comment`로 대체된다. `summary`는 남고, 맨 위에 쓸 `one_line`이 추가된다.

| 키 | 내용 | 놓이는 자리 | 비고 |
| --- | --- | --- | --- |
| `one_line` | 오늘 시장 한 줄 (1~2문장) | ① TODAY IN ONE MINUTE | 신규 |
| `regime_echo` | `analysis.regime.label`을 그대로 복창 | 본문에 안 나감 | 신규 — 일관성 검증용 |
| `regime_comment` | 점수와 구성 요소가 왜 이렇게 나왔는지 | ② MARKET REGIME | `market_mood` 대체 |
| `summary` | 지수 흐름 요약 3~5문장 | ③ MAJOR INDEX | 기존 |
| `breadth_comment` | 지수 대비 시장 폭이 말하는 것 | ④ MARKET BREADTH | 신규 |
| `sector_comment` | 오늘의 주도/약한 섹터 해설 | ⑤ SECTOR ROTATION | 신규 |
| `rates_comment` | 금리 · 경제지표 · 금리 ↔ 성장주 해설 | ⑥ RATES & MACRO | `macro_comment` 확장 |
| `gainers_comment` `attention_comment` | 기존 | ⑦ MARKET LEADERS | 기존 |
| `news[]` | `{ index, why, theme, related: ["NVDA","SMH","QQQ"] }` 3~5개 | ⑨ KEY NEWS | `theme` `related` 신규 |
| `change_comment` | 1D/5D/20D · 연속성 · 위치가 말하는 추세 변화 | ⑩ WHAT CHANGED | 신규 |
| `risk` | 기존 (줄바꿈 구분 2~5개) | ⑪ RISK MAP | 기존 |
| `watch[]` | `{ id, why }` — `analysis.watch`의 id마다 한 문장 | ⑫ TOMORROW WATCH | 신규 |
| `opinion` | 현재 시장 상태 2~3문장 — 행동 지시 없이 | ⑬ FINAL VIEW | 기존 |
| `image_prompt` | 기존 | 커버 | 기존 |

### 뉴스 → 자산 → 실제 반응

`related`가 들어오면 렌더가 **그 심볼들의 실제 1D 등락률을 `analysis.series`와 `raw`에서 꺼내** 붙인다.
Gemini는 심볼만 고르고, 숫자는 파이썬이 채운다.

```
[AI/반도체]  Nvidia, 차세대 데이터센터 투자 확대 발표
             NVDA +3.2%   SMH +2.1%   QQQ +1.3%
             → 선정 이유: AI 인프라 투자 지속 기대가 반도체 전반으로 확산
```

이렇게 되면 뉴스 5건이 "무슨 일이 있었다"에서 "무슨 일이 있었고 시장은 이렇게 반응했다"로 바뀐다.

### 톤 — 상태를 말하고 행동은 말하지 않는다

❌ NVDA를 매수해야 합니다.
⭕ NVDA는 단기 상승 추세를 유지하고 있으나 20일 고점과의 거리가 좁아져 변동성 확대 가능성을 관찰할 필요가 있습니다.

프롬프트에 이 예시 쌍을 그대로 넣는다. 규칙 5("권유 금지")만으로는 "~에 주목할 시점"류의 우회 표현이 나온다.

## D. 검증 확장 — 새 출력도 구조로 잡는다

> `validate_report.py`의 `REQUIRED_LLM_KEYS`와 검사 항목 추가

## F. 이력 저장 — report-state 브랜치

> 구현됨 — `test-daily-report.yml`의 `Load analysis history` · `Save analysis history` 스텝.
> `comment-reply.yml`의 `comment-state` 패턴과 동일. 로컬 경로는 `output/state/`

가격에서 다시 계산할 수 있는 값은 저장하지 않는다. 저장하는 것은 **우리가 만든 점수와 라벨**,
그리고 나중에 임계값을 조정할 때 필요한 그날의 입력값이다.

| 무엇 | 어디 | 형식 |
| --- | --- | --- |
| 일별 `analysis.json` (raw 제외) | `history/{date}.json` | 하루 한 파일 |
| 점수 시계열 요약 | `history/regime.jsonl` | 한 줄에 `{date, score, label, components, status.overall, breadth.ratio, vix, us10y}` |

**로드** (파이프라인 맨 앞): `git fetch origin report-state:refs/report-state` 뒤
`git archive refs/report-state <state 경로> | tar -x`로 디렉터리째 꺼낸다.
`actions/checkout`이 fetch refspec을 `main`으로 좁혀두기 때문에 **목적지 ref를 명시하지 않으면 FETCH_HEAD만
갱신되고 ref가 안 만들어진다** — `comment-reply.yml`이 이미 밟은 함정이다.

**저장** (게시 뒤, `if: always()`): orphan 체크아웃 → `git reset` → `git add -f` → force push.
`output/`이 `.gitignore` 대상이라 `-f`가 없으면 `git add`가 종료코드 1로 죽는다.

브랜치를 따로 쓰는 이유는 `gh-pages`가 jsDelivr로 **공개 서빙**되기 때문이다. 분석 이력은 공개할 이유가
없고, 매일 커밋이 쌓이면 `gh-pages`의 `keep_files` 배포와도 엉킨다.

이력이 없는 날(첫 실행 · fetch 실패)은 `regime.score_prev = null`로 진행하고 경고만 남긴다.
그날 리포트를 막을 이유는 아니다.

## 바뀌지 않는 것

- **원칙.** Gemini는 숫자 · 점수 · 라벨 · 레벨을 만들지 않는다. 늘어나는 것은 파이썬이 계산하는 숫자의 종류다.
- **검증 게이트.** 오류면 미게시, 경고면 진행. 새 출력도 같은 두 갈래로만 나눈다.
- **커버 이미지** 경로 (Pollinations → HF → gh-pages → jsDelivr) 와 밝은 톤 규칙.
- **게시와 중복 방지.** `report_title.py`의 제목 규칙, `check_published.py` + `publish_saved.py` 이중 방어.
- **스케줄.** 화~토 06:00 KST. 월요일 아침 리포트는 원래 없다 — 직전 미국장(금요일)은 토요일 리포트가 이미 다뤘다.
- **API 키.** 새로 발급받을 것이 없다.

# 운영

## 운영 — 언제 돌고, 무엇이 필요한가

### 스케줄

| cron (UTC) | KST | 용도 |
| --- | --- | --- |
| `0 21 * * 1-5` | **화~토** 06:00 | 정규 실행 — 직전 미국장 마감(05:00 KST) 1시간 뒤 |
| `30 22 * * 1-5` | 화~토 07:30 | 누락 대비 재시도 |
| `workflow_dispatch` | 수시 | 수동 — `publish` 체크 시에만 실제 게시 |

cron의 `1-5`는 UTC 요일이다. 21:00 UTC에 9시간을 더하면 KST 다음 날이 되므로 실제 게시 요일은
화~토가 된다. 일요일 UTC(= 월요일 KST 아침)는 스케줄에 없고, 있어야 할 이유도 없다.

동시성 그룹은 `daily-report`이고 `cancel-in-progress: false`다.
재시도 cron이 진행 중인 정상 실행을 죽이면 안 되기 때문에, 취소 대신 큐에서 기다린다.
실행이 끝나면 `output/` 전체가 아티팩트로 올라가 사후 확인이 가능하다.

| `BLOGGER_CLIENT_SECRET` | 게시 시 | 〃 |
| `BLOGGER_REFRESH_TOKEN` | 게시 시 | 〃 |
| `BLOG_URL` | 선택 | 기본 `alpha-scope.blogspot.com` |
| `PUBLISH_BLOG` | 선택 | `true`면 `--publish` 없이도 게시 |
| `BREADTH_MODE` | 선택 (2부) | `proxy` (기본) / `full` / `auto` — 전수 시도 후 커버리지 미달이면 프록시 |

### 직접 돌려보기

```bash
# 수집부터 HTML까지만 (기본값 — 아무것도 게시되지 않는다)
python experiments/daily-report/main.py

# 실제 게시
python experiments/daily-report/main.py --publish

# (2부) 분석만 다시 — report_input.json이 있으면 네트워크 없이 돈다
python experiments/daily-report/analyze.py
```

dry-run이 끝나면 `output/report.html`을 브라우저로 열어 그날 본문을 그대로 확인할 수 있다.
로컬에는 `report-state`가 없으므로 `regime.score_prev`는 `null`로 나온다 — 정상이다.

## 글이 안 올라갔다면 여기 중 하나다

기본 태도는 **"애매하면 올리지 않는다"**이다. 틀린 숫자나 깨진 이미지가 올라가는 것보다
그날 리포트가 없는 편이 낫다는 전제로 만들어져 있다. 유일한 예외는 게시 여부 확인 실패인데,
그건 2차 방어가 받쳐주기 때문이다.

| 단계 | 조건 | 확인할 것 |
| --- | --- | --- |
| — | 월요일 아침 | 정상. 스케줄에 없는 날이다 |
| 01 수집 | `yf.download`가 빈 프레임 | Yahoo 일시 장애. 재시도 cron이 받는다 |
| 01.5 분석 | `series.SPY` 결측 · `regime.score` 범위 밖 | 시계열 길이 부족(휴장 연속) · 규칙 버그 |
| 02 Gemini | 모든 API 키 소진 | 키 만료 · 할당량 초과 · 모델명 오타 |
| 03 검증 | 지표/지수 결측 또는 LLM 출력 불량 | 로그에 누락 항목이 이름으로 전부 찍힌다 |
| 03 검증 | `regime_echo` 불일치 | Gemini가 점수를 반대로 읽음. 프롬프트 규칙 9 확인 |
| 04 이미지 | Pollinations · Hugging Face 모두 실패 | 게시 실행에서만 중단. dry-run은 경고 후 계속 |
| 06 게시 | 커버 URL이 200이 아님 | gh-pages 배포 실패이거나 CDN 반영 전 |
| 06 게시 | 같은 제목의 글이 이미 존재 | 정상 동작 — 재시도 cron이 중복을 피한 것 |
| 07 이력 | `report-state` push 실패 | 리포트는 이미 게시됨. 다음 날 `score_prev`만 `null` |

---

수집 대상이나 프롬프트 규칙을 바꾸면 `validate_report.py`의 필수 키 목록도 같이 손봐야 한다.
2부의 임계값(B-8 · B-9 · B-10)을 바꿀 때는 `history/regime.jsonl`로 과거 날짜에 어떤 라벨이 붙었을지
먼저 확인하고 바꾼다 — 그게 이력을 쌓는 이유다.
