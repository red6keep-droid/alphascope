# 엔비디아 데일리 리포트 — 기획

NVDA 한 종목에 대해 **주가에 영향을 줄 만한 이벤트를 매일 수집·판정**하고, 3년 보유자가 실제로 보는 **보유 논리 점검표**와 함께
"엔비디아 데일리 — YYYY년 M월 D일" 글을 만든다. 기존 [데일리 리포트](데일리-리포트-파이프라인.md)·[트럼프 트렌드](트럼프-SNS-트렌드-리포트-기획.md)의
설계 원칙 — 숫자는 파이썬이, 문장은 Gemini가 — 을 그대로 따른다.

작성일: 2026-10-07 · 선행 문서: [엔비디아-리포트-이벤트-정의.md](엔비디아-리포트-이벤트-정의.md) (이벤트 48개 브레인스토밍 → 수집 가능 33개 확정) ·

이 리포트의 질문은 "오늘 사야 하나"가 아니다.
**"내가 이 주식을 들고 있는 이유 중 오늘 바뀐 것이 있는가, 그리고 다음 분기 점검표의 어느 칸이 꺾이고 있는가"** 다.
트럼프 리포트에서 배운 것 하나를 못 박는다 — **"오늘 바뀐 것"이 비는 날이 많아야 정상이고, 억지로 헤드라인을 채우지 않는다.**

## 0. 먼저 알아둘 것 — 이 리포트가 하지 않는 것

- **매수·매도 신호를 만들지 않는다.** 알파 종목 리포트와 역할이 다르다. 이 글은 보유 종목의 사실 추적이다.
- **이벤트 → 수익률 통계를 1차에 넣지 않는다.** 종목 하나라 영역별 표본이 연 수 건이다. 트럼프 이벤트(9절)만 기존 통계를 가져오고 나머지는 사실만 기록한다. 1년치가 쌓이면 재검토.
- **CEO SNS를 수집하지 않는다.** 젠슨 황은 개인 SNS 계정을 운영하지 않는다. CEO 발언은 실적 보도자료·10-Q·공식 뉴스룸·키노트 캘린더로 대신한다.
- **유료·불안정 소스를 쓰지 않는다.** 기관 실시간 순매수, 다크풀, 옵션 스윕, 레딧, 구글 트렌드는 제외. 대리 지표는 거래량 배수·OI 변화·기사 수.
- **감성 점수를 만들지 않는다.** 뉴스는 "영역·방향·신규성·관련성"으로 분류할 뿐 긍정/부정 점수를 합산하지 않는다.

## 2. 수집 — 다섯 묶음

| 묶음 | 모듈 | 하는 일 | 저장 |
| --- | --- | --- | --- |
| 시세·옵션·추정치 | `collect_market.py` | 일봉(기존) · 옵션 체인 스냅샷 · 추정치 · 애널리스트 · 보유·공매도 | `daily_bars` · `option_snapshots` · `daily_state` |
| EDGAR | `collect_edgar.py` | submissions JSON에서 전일 이후 신규 공시 → Form 4는 XML 파싱(거래자·거래일·수량·가격·10b5-1 플래그), 8-K는 Item 목록, 10-Q/10-K는 본문 저장 | `items` (kind=`form4`/`8k`/`10q`) · `filings_text` |
| 규제·법원 | `collect_regulatory.py` | Federal Register 검색(어제 이후, 용어 3개: `Nvidia` · `advanced computing` · `semiconductor export`) · CourtListener 신규 도켓 + 추적 도켓 신규 문서 | `items` (kind=`fedreg`/`court`) · `cases` |
| 뉴스 | `collect_feeds.py` | 뉴스룸·블로그·CNBC·Reuters/Google News RSS → NVDA 키워드 1차 필터 → 제목·요약·링크·발행시각만 | `items` (kind=`newsroom`/`blog`/`news`) |
| 캘린더·월간 | `collect_calendar.py` | 실적일 12종목 · FOMC/FRED(기존) · GTC/Computex/CES/리밸런싱(정적 JSON) · TSMC 월매출 · ETF 발행주식수 | `calendar` · `monthly` · `daily_state` |

수집은 **새 것만** 넣는다. 기준 키는 소스별 고유 ID(EDGAR accession, Federal Register document_number, CourtListener docket_id+entry, RSS guid 또는 링크 해시).
RSS 기사 본문은 저장하지 않는다. 뉴스룸 보도자료는 공식 1차 자료이므로 본문을 저장한다.

## 3. 저장 — SQLite 테이블

`experiments/nvda-report/data/nvda.db`. trump-trend와 같은 방식으로 상태 브랜치 `nvda-state`에 CSV/JSONL로 내보내고 불러온다.

### `items` — 수집된 문서 하나 = 행 하나

| 컬럼 | 채우는 쪽 | 설명 |
| --- | --- | --- |
| `item_id` | 수집 | PK. `{kind}:{source_key}` |
| `kind` | 수집 | `form4` · `8k` · `10q` · `fedreg` · `court` · `newsroom` · `blog` · `news` |
| `published_at` | 수집 | 원문 시각 (UTC) |
| `title` / `summary` / `url` | 수집 | 제목 · 요약(RSS는 피드 요약, 공시는 첫 500자) · 원문 링크 |
| `source` | 수집 | `edgar` · `federalregister` · `courtlistener` · `nvidianews` · `cnbc` … |
| `raw_json` | 수집 | 소스별 구조화 필드 (Form 4 거래 내역, 8-K Item 번호, 도켓 ID 등) |
| `prefilter_reason` | 파이썬 | 1차 탈락 사유. `no_nvda_keyword` · `duplicate_of:{item_id}` · NULL |
| `ai_area` | Gemini | 4절 enum. 영역 하나 |
| `ai_direction` | Gemini | `positive` · `negative` · `uncertain` · `neutral` |
| `ai_novelty` | Gemini | `new` · `update` · `repeat` (5절) |
| `ai_relevance` | Gemini | 0–3. NVDA 주가와의 직접 연결 |
| `ai_fact` | Gemini | **한 문장 사실 요약** (한국어, 수치는 원문에 있는 것만) |
| `ai_entities` | Gemini | JSON — 언급 기업 티커 · 국가 · 제품명 |
| `is_event` | 파이썬 | 6절 임계값 통과 여부 |
| `analyzed_at` | 분류 | NULL이면 분류 대기 |

### `daily_state` — 거래일 하나 = 행 하나 (상태판 스냅샷)

| 컬럼군 | 내용 |
| --- | --- |
| 가격 | `close` · `ret_1d` · `ret_vs_spy` · `ret_vs_smh` · `ret_vs_amd` · `gap` · `range_pct` |
| 거래량 | `volume` · `vol_ratio_20d` |
| 기술 | `ma50` · `ma200` · `pct_from_52w_high` · `rsi14` · `ma_cross` (`golden`/`death`/NULL) |

## 4. 분류 — Gemini가 라벨을 붙이고 파이썬이 판정한다

### 4-A. Gemini — 문서 하나를 구조화한다

입력: `title · summary · source · kind · published_at · 최근 7일 같은 kind의 ai_fact 목록(신규성 판단용, 최대 20개)`.
출력 JSON 한 개. 항목별 검증(enum 밖·범위 밖·필수 누락 → 재시도 1회 → 실패 시 `analyzed_at`에 실패 표시, 리포트에서 제외).

**영역 enum (`ai_area`)** — 이벤트 정의 문서 1절의 영역을 그대로 쓴다.

| 영역 | 포함 |
| --- | --- |
| `Earnings` | NVDA·고객·공급·동종 실적, 가이던스, 컨센서스 |
| `Flows` | 내부자, 기관, ETF, 공매도, 자사주 |
| `Regulation` | 수출 규제, 관세, 중국 조치, 반독점, AI 규제, 보조금 |
| `Legal` | 소송, 판결, 합의 |
| `Product` | 신제품, 로드맵, 지연, 벤치마크, 경쟁 제품 |
| `Demand` | 대형 계약, 데이터센터 투자, 고객 자체 칩, 전력 제약 |
| `Supply` | TSMC, CoWoS, HBM, 대만 지정학 |
| `Corporate` | M&A, 투자, 임원, 키맨, 분할·배당 |
| `Macro` | 금리·거시 (대부분 1차 필터에서 걸러짐) |
| `Other` | 위에 없음. 관련성 0 강제 |

**방향 (`ai_direction`)** — `positive` · `negative` · `uncertain`(불확실성 증가) · `neutral`.
트럼프 기획과 같은 원칙: **시장 영향 크기를 Gemini가 매기지 않는다.** 관련성(0–3)은 "NVDA와 직접 연결되는가"이지 "주가가 얼마나 움직일까"가 아니다.

**관련성 기준표 (`ai_relevance`)**

| 값 | 기준 | 예 |
| --- | --- | --- |
| 3 | NVDA가 당사자이고 숫자·조치가 구체적 | 수출 라이선스 취소, 실적 가이던스, 대형 계약 금액 명시 |
| 2 | NVDA가 당사자이나 조치가 모호, 또는 핵심 고객·공급사의 구체적 조치 | 하이퍼스케일러 capex 상향, TSMC 월매출, 특허 소송 접수 |
| 1 | 섹터·산업 일반, NVDA는 언급만 | AI 산업 전망 기사, 경쟁사 신제품 보도 |
| 0 | 무관 또는 홍보성 | 컨퍼런스 참가 안내, 수상 소식 |

### 4-B. 파이썬 — 판정과 계산은 코드가 한다

- 이벤트 여부(6절), 상태판 숫자(7절), 캘린더 D-n, 소송 상태 전이는 전부 파이썬.
- Form 4·8-K는 Gemini를 거치지 않는다. 구조화된 공시라 파싱으로 충분하다. 8-K 본문이 길고 Item 8.01(기타)일 때만 Gemini에 한 줄 요약을 시킨다.
- 실적 보도자료(8-K Item 2.02 첨부)에서 분기 수치를 Gemini가 추출하되, **파이썬이 원문에서 같은 숫자 문자열을 찾지 못하면 버린다.** 추출 실패는 "미수집"으로 남기고 다음 날 재시도.

## 5. 중복과 신규성

트럼프 리포트에서 가장 아팠던 것이 "같은 뉴스가 다른 라벨로 쪼개져 급상승 상위를 차지"하는 문제였다. 여기서는 처음부터 두 단계로 막는다.

**① 파이썬 중복 제거 (분류 전).** 같은 날 수집된 `news` 항목끼리 제목 정규화(소문자·구두점 제거·회사명 통일) 후 토큰 자카드 유사도 ≥ 0.6이면 뒤의 것에 `prefilter_reason = duplicate_of:{앞의 item_id}`. 뉴스룸·공시가 있으면 그것을 대표로 삼고 외부 기사는 전부 중복 처리.

**② Gemini 신규성 (`ai_novelty`).** 최근 7일 같은 영역의 `ai_fact` 목록을 함께 주고 판정한다.

| 값 | 뜻 | 리포트 취급 |
| --- | --- | --- |
| `new` | 7일 안에 없던 사실 | 이벤트 후보 |
| `update` | 알려진 사안의 진전 (판결, 승인, 수치 확정) | 이벤트 후보. "진행 중 사안"의 `last_activity` 갱신 |
| `repeat` | 같은 사실의 재보도·해설 | 상태판 기사 수에만 집계. 이벤트 아님 |

링크 글·헤드라인 재인용 문제는 소스 선택으로 피한다. 뉴스룸·EDGAR·연방관보·법원은 1차 자료이고, 외부 기사는 `repeat`이면 자동 탈락한다.

## 6. 이벤트 판정 — 임계값 표

`is_event = true`가 되는 조건. 이 표가 "오늘 바뀐 것" 섹션을 결정한다. 숫자는 전부 **초안**이며 첫 30일 뒤 하루 평균 1~3건이 되도록 조정한다(확정값 표 참조).

| 구분 | 조건 (하나라도) |
| --- | --- |
| 문서형 (`items`) | `ai_relevance ≥ 2` **and** `ai_novelty ∈ {new, update}` **and** `prefilter_reason IS NULL`. **Legal·Regulation은 relevance ≥ 1** (2026-10-10 사용자: 법적 기사는 꼼꼼히 — 전용 Google News 쿼리·규제 키워드 예외·2차 출처 강등과 함께, README ③ 표) |
| Form 4 | 신규 1건 이상. 10b5-1 계획 매도는 금액만 표기, **계획 외 거래·매수·10% 보유자 거래는 강조** |
| 8-K | 신규 1건 이상. Item 2.02(실적)·1.01(중요 계약)·5.02(임원)·8.01(기타, Gemini 요약 후 관련성 ≥ 2) |
| 가격·거래량 | `vol_ratio_20d ≥ 2.0` · `range_pct ≥ 4%` · `abs(ret_vs_spy) ≥ 3%` · `ma_cross` 발생 · `pct_from_52w_high ≥ −2%`(신고가권 진입일만) |
| 옵션 | `iv_rank_60d ≥ 80 or ≤ 20`(이력 확보 후) · `pc_ratio_oi` 전일 대비 ±20% · 특정 행사가 OI 전일 대비 2배 이상(OI ≥ 10,000 한정) |
| 추정치 | `eps_est_cq_7d_chg_pct` 또는 `rev_est_cq_7d_chg_pct` 절대값 ≥ 1% · 30일 상향/하향 건수 비 ≥ 3:1 |
| 애널리스트 | 등급 변경 1건 이상 (목표가만 바뀐 것은 상태판) |
| 수급 | ETF 발행주식수 5일 변화 ±2% · 공매도 잔고 전 회차 대비 ±15% |
| 캘린더 | 실적 D-1·D0·D+1 · 고객·공급사 실적 D0 · TSMC 월매출 발표일 · FOMC D0 · GTC/Computex/CES D0 |
| 트럼프 | 9절 조건 |

이벤트가 0건인 날은 "특이 이벤트 없음" 한 줄로 끝낸다. 이벤트가 8건을 넘으면 관련성·신규성·거래량 순으로 상위 8건만 본문, 나머지는 접힘 목록.

## 7. 상태판 — 매일 계산하는 숫자

| 지표 | 계산 | 비고 |
| --- | --- | --- |
| 거래량 배수 | `volume / mean(volume[-20:])` | 트럼프 `rel_volume`과 동일 정의 |
| 상대 수익률 | `ret_1d(NVDA) − ret_1d(SPY · SMH · AMD)` | SPY 차감은 트럼프 `abn_*`과 동일 |
| 50/200일선 | 단순이동평균. 교차는 전일 대비 부호 변화 | |
| RSI14 | Wilder 방식 | |
| 52주 고점 대비 | `close / max(high[-252:]) − 1` | |
| ATM IV 30일 | 가까운 만기 2개의 ATM 콜·풋 IV를 만기 가중 보간 | yfinance IV는 거래소 계산값 |
| IV 랭크 60일 | `(iv − min60) / (max60 − min60)` | **스냅샷 60일 쌓인 뒤 활성.** 그 전엔 "집계 중" |
| implied move | 다음 실적 직후 만기의 ATM 스트래들 가격 / 현재가 | 실적 D-30부터 표시 |

| GEX 근사 | `Σ(call_oi × γ) − Σ(put_oi × γ)` × 100 × spot, γ는 Black-Scholes(IV·잔존일·무위험 4%) | 딜러 포지션 가정이 조잡하다. **부호와 0 근처 행사가만** 보고 크기는 쓰지 않는다 |
| 추정치 7일 변화 | 오늘 컨센서스 / 7일 전 스냅샷 − 1 | `daily_state` 이력에서 |
| 기사 수 배수 | 오늘 NVDA 기사 수 / 7일 평균 | `repeat` 포함 전체 |

## 9. 트럼프 파이프라인 연결

trump-trend DB에서 NVDA 관련 이벤트를 뽑는 조건:

```sql
SELECT * FROM trump_events
WHERE date(first_post_at) = :day
  AND (
    affected_companies LIKE '%NVDA%'
    OR mapping_rule_id IN ('trade_china_semis', 'trade_semis_sector')
    OR (topic = 'Company' AND affected_companies LIKE '%NVDA%')
  )
  AND event_intensity >= 5
```

리포트에는 이벤트 한 줄(주제·강도·방향·매핑 경로)과 **같은 규칙의 과거 clean 이벤트에 대한 NVDA·SMH 초과 반응 통계(N·중앙값·p·q)** 를 trump-trend `aggregate` 결과에서 가져와 붙인다. 통계가 `robust`가 아니면 "발언 없는 날과 구분되지 않음"을 명시한다.

실행 순서: 같은 시각(22:30 UTC)에 두 워크플로가 돌면 경쟁한다. **NVDA 워크플로는 22:45 UTC**로 15분 늦추고, `trump-state` 브랜치에서 그날의 `trump_analysis.json`과 이벤트 목록을 읽는다. trump-trend가 그날 실패했으면 전날 것을 쓰고 "트럼프 데이터 전일 기준"을 표기.

## 12. Gemini 호출

- `gemini_client.py`(다중 키 라운드로빈·429 쿨다운·503 백오프)를 **그대로 가져온다**(복사 아닌 import 경로 공유 여부는 구현 때 결정).
- 하루 호출량: 분류 1~2배치(문서 20~40건) + 8-K 요약 0~1 + 분기 추출 0~1 + 서술 0~1. **trump-trend의 1/5 수준.**
- 분류 프롬프트는 `prompts/classify.txt`에 영역 enum·관련성 기준표·신규성 규칙·금지 사항(수치 창작 금지, 원문에 없는 티커 금지)을 넣는다.
- 추출 프롬프트는 "원문에 있는 숫자 문자열을 그대로" 규칙. 파이썬이 `value` 문자열을 원문에서 `find`하지 못하면 폐기.

순서에 못 박아 둘 것:

- **스키마(`items.kind`·`ai_*` 컬럼·`daily_state` 컬럼군·`quarterly.metric` 목록)는 ② 전에 확정한다.** 분류는 백필할 수 있지만 컬럼을 나중에 바꾸면 전부 다시 돈다.
- **옵션 스냅샷은 ①부터 매일 쌓는다.** IV 랭크는 60일, 선행 PER 분위는 1년이 쌓여야 켜진다. 늦게 시작할수록 늦게 켜진다.
- **③의 소송 초기화는 수동 검토를 거친다.** 433건을 전부 추적하지 않는다. 증권·반독점·최근 1년 접수 특허 소송 정도로 시작.
- **③의 도켓은 분류하지 않는다 (2026-10-10 사용자).** 일일 리포트이므로 주가에 영향 줄 판결이 예정될 때만 미리 경고한다. 절차 문서·상태 전이 로그는 만들지 않는다. 1절 #30·31의 "Gemini가 판결·합의·기각·일정으로 분류"는 규칙(정규식)으로 대체.

지금 만들지 않는 것: 13F 직접 파싱, 실적 콜 녹취록 자동 수집, 이벤트별 수익률 통계(트럼프 제외), 분봉, 소셜 멘션, 매수·매도 신호.

설계 원칙은 같다. **숫자는 파이썬이 계산하고 Gemini는 문장만 쓴다.** 여기서 Gemini의 자리는 셋 — 문서 분류(입력), 보도자료 수치 추출(입력, 원문 대조 필수), 서술(출력). 이벤트 판정·상태판·점검표 계산은 전부 파이썬 쪽에 있다.
